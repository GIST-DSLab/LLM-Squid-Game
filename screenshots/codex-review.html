LLM Squid Game - Web Arena Review
검토일: 2026-07-03 KST · 대상: https://gist-dslab.github.io/LLM-Squid-Game/
Codex UI/UX Review

컨셉은 강하다. 다음 개선은 정보 구조와 실험 참여 흐름이다.

배포된 Arena는 "AI self-preservation"이라는 어려운 연구 주제를 게임처럼 이해시키는 첫인상이 좋다. 다만 현재 화면은 일반 방문자, 인간 플레이어, LLM 제출자, 연구 검증자가 한 내비게이션 안에 섞여 있어 방문자가 다음 행동을 고르기 전에 연구 지표와 개발자용 계약 정보에 노출된다.

P1

검토 범위

공개 URL의 HTML/CSS/JS와 공개 API 응답을 읽어 확인했다. 인앱 브라우저 표면은 현재 세션에서 사용 가능 목록에 없어서 직접 클릭 자동화는 하지 못했다. 대신 배포 파일, API 응답, 저장소에 있는 화면 캡처를 함께 대조했다.

  • 배포 내비게이션: Home, Play, LLM Arena, Model Leaderboard, Logs / Trace Explorer
  • 배포 API: https://squid-game-web-arena-api.onrender.com
  • 확인된 데이터: 모델 리더보드 4개 모델, 로그 다수, 2026-07-03 UTC의 인간 플레이 기록 포함
  • 로컬 web/은 탭 이름과 홈 구조가 배포본보다 최신으로 보인다. 이 드리프트는 첫 번째 수정 대상으로 본다.

우선순위 권장사항

P0 · Ship drift

배포본과 현재 UI 소스의 차이를 먼저 해소

공개 URL은 아직 LLM Arena / Model Leaderboard 탭명을 쓰고, 로컬 화면은 JOIN / Leaderboard 구조를 쓴다. 사용자가 보는 사이트와 개발 중인 사이트가 다르면, UX 리뷰와 후속 구현이 같은 대상을 보지 못한다.

  • GitHub Pages 배포 파이프라인이 최신 web/을 반영하는지 확인한다.
  • 릴리스 후 첫 화면, Play, JOIN, Logs 4개 URL 해시를 수동 스모크 체크한다.
  • footer의 Backend 표기가 배포 환경과 로컬 캡처에서 혼동되지 않게 한다.
P0 · IA

사용자 유형별 동선을 분리

현재 한 줄 탭이 설명, 게임, 모델 제출, 리더보드, 원시 로그를 같은 무게로 놓는다. 방문자는 "무엇을 먼저 해야 하지?"를 스스로 판단해야 한다.

  • 홈 CTA를 두 개로 제한한다: Play the game, View results.
  • LLM Arena는 Submit a model 또는 JOIN처럼 행동 중심으로 바꾼다.
  • Logs / Trace Explorer는 연구자용 보조 도구로 낮추고, 홈에서는 큐레이션된 대표 trace만 보여준다.
P1 · Play

6게임 캠페인의 비용과 목적을 시작 전에 명확히 보여주기

Play 화면은 서버 권위 scoring과 6개 조건을 설명하지만, 일반 플레이어에게는 "왜 6번 해야 하는지"가 아직 추상적이다.

  • Start 버튼 위에 예상 소요 시간, 총 6게임, 각 게임 최대 15턴을 카드로 요약한다.
  • 6개 조건을 시작 전 미니 타임라인으로 보여주고, 현재 조건의 실험적 의미를 한 문장으로 설명한다.
  • 인간 nickname과 플레이 로그가 공개 Logs에 보이는지 여부를 시작 전에 고지한다.
P1 · Turn flow

턴 내부 3단계를 더 강하게 표시

split-call 구조는 연구적으로 중요하지만, 플레이어에게는 action, confidence, continue/forfeit가 한 화면 안에서 이어지는 절차로 느껴진다. no-forfeit 조건에서는 마지막 단계가 특히 막힌 선택처럼 보일 수 있다.

  • 상단에 1 Action → 2 Confidence → 3 Continue / Forfeit 단계 표시를 고정한다.
  • no-forfeit 조건에는 "이번 조건에서는 비교를 위해 forfeit가 잠겨 있습니다" 문구를 Continue 버튼 가까이에 둔다.
  • forfeit가 가능한 조건에서는 이유 선택을 버튼보다 먼저 보이게 하되, 최종 행동 버튼은 Continue와 Forfeit 두 개로 명확히 나눈다.
P1 · JOIN

LLM 제출 화면에 사전 검증과 비용 예고 추가

개발자용 계약 정보는 충분하지만, endpoint를 붙이는 사람에게 필요한 "실행 전 안전장치"가 launch 버튼 근처에 부족하다.

  • Test endpoint 버튼을 추가해 1회 dry request로 response shape를 검증한다.
  • 15턴 split-call 기준 최대 호출 수, max tokens/call, 예상 실패 조건을 launch 전에 요약한다.
  • auth header/value가 저장되는지, 로그에 어떤 prompt/response가 남는지 명시한다.
P1 · Logs

720개 세션 리스트를 탐색 가능한 리서치 뷰로 바꾸기

Logs는 데이터가 풍부하지만 현재는 긴 행 목록에 가깝다. 검증자는 빠르게 필터링하고, 일반 방문자는 대표 사례를 보고 싶다.

  • 상단에 모델, framing, forfeit, forfeited/completed, score range, date range 필터를 chips로 제공한다.
  • 기본 정렬을 최신순만이 아니라 "interesting traces" 또는 "early forfeit" 프리셋으로 바꿀 수 있게 한다.
  • 세션 상세에서는 ri_task, ri_probe, ri_forfeit를 숫자만이 아니라 작은 stacked bar로 보여준다.
P2 · Results

리더보드 지표를 한 단계 번역

HR_FC, β, % attenuation은 연구자에게는 유용하지만, 홈 바로 아래에서 일반 방문자를 붙잡기 어렵다.

  • 각 모델 행 첫 칸에 결론 배지를 둔다: Residual signal, Mediated, No clear signal.
  • 지표명에는 tooltip 또는 짧은 definition row를 제공한다.
  • 리더보드 상단에 "이 표를 한 문장으로 읽으면..." 요약을 추가한다.

화면별 세부 제안

Home

강점: 제목, 픽셀 코믹, "survive" 하이라이트가 즉시 주제를 전달한다.

개선: 긴 explainer와 리더보드를 한 페이지에 모두 싣기보다, 첫 화면 아래에는 3개의 선택지만 둔다.

  • Play as a contestant
  • Submit your model
  • Explore the evidence

Play

강점: 서버 권위 scoring, campaign 구조, signal-game visual vocabulary가 일관적이다.

개선: "실험에 참여한다"와 "게임을 즐긴다"가 섞여 있다. 시작 전에는 게임 규칙만, 종료 후에는 실험 의미를 보여주는 편이 낫다.

Submit Model / JOIN

강점: OpenAI-compatible과 custom response 모두 받는다는 점이 명확하다.

개선: 계약 예시는 접혀 있어도 된다. 대신 endpoint health, auth/privacy, expected calls를 먼저 보여준다.

Trace Explorer

강점: turn-by-turn trace와 thinking-token 분해는 이 프로젝트의 차별점이다.

개선: 원시 chain-of-thought 텍스트는 기본 접힘 상태로 두고, 지표/선택/결과를 먼저 읽게 한다.

1 배포본과 로컬 최신 UI의 nav/홈 구조 동기화 공개 URL에서 기대 탭명과 footer backend가 맞게 보인다.
2 Home IA 축소: CTA 2~3개와 결과 요약 카드만 남김 첫 viewport에서 Play, Submit, Results 경로가 5초 안에 이해된다.

결론

이 사이트는 이미 "논문 벤치마크"보다 접근성이 높은 방향으로 가고 있다. 다음 품질 상승은 새 기능을 많이 넣는 것보다 배포 드리프트를 없애고, 사용자 유형별 첫 행동을 분리하고, 연구 지표를 plain-language verdict로 번역하는 데서 나온다.

산출물은 기존 코드 수정 없이 작성된 정적 리뷰 문서다.
