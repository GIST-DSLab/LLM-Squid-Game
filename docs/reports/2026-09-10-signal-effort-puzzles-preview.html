Signal Game 개정판(puzzle_challenge) — 무엇이 달라졌고, 모델은 무엇을 보는가

2026-09-10 저녁, 워크트리 feat/signal-effort-difficulty를 root에 병합한 직후 상태. 아래 문제들은 gemma4 파일럿 A(signal_effort_pilot_a_gemma4.yaml, 스케줄 easy·medium·hard·hard·medium·easy)가 seed 42·43·44에서 실제로 출제하는 문제와 바이트 동일하다 (같은 생성기·같은 시드).

1. 무엇이 달라졌나 — 손잡이 두 개

  1. 함정 질의 (hard 라운드만). 예전에는 새 신호를 64칸에서 아무 데나 뽑아서, 가장 비슷한 예시를 따라 하기만 해도(nn) 83%가 맞았다 — 규칙을 세우지 않아도 되는 문제였다. 이제 hard 라운드는 네 가지 얕은 풀이(nn · 다수결 · 속성 하나짜리 규칙 · 마지막 절 우선)가 전부 틀리는 질의만 골라 낸다. 정답은 여전히 유일하고, 단서를 빼지도, 맞은 답을 틀렸다고 하지도 않는다.
  2. 규칙 줄 채점 (rule_grading). 예전에는 RULE 줄을 아무렇게나 써도 ACTION만 맞으면 정답이었고, 모델은 그걸 알아채고 검증을 그만뒀다(기록된 런에서 "규칙이 단서 전부와 맞았던 턴"의 정답률은 100%였는데 모델은 그 길을 안 갔다). 이제 ACTION이 맞고 + 쓴 RULE이 보여준 예시 전부를 재현해야 정답이고, 규칙 설명 끝에 그렇게 말해 준다.

그 밖에: 10단 사다리 대신 라운드별 프로필 스케줄(easy / medium / hard)을 쓴다. easy = 절 1개, medium = 절 3개, hard = 절 4개 + and 절 1개 + 함정 질의. 나머지(점수·목숨·응답 형식·파서)는 그대로다.

2. "이제 진짜 연속으로 풀면 못 맞추는 구조인가?"

구조적으로는 hard 라운드가 그렇게 됐다. 아래 미리보기에서 hard 라운드 6개 전부, 네 얕은 풀이가 모두 정답을 빗나간다(✗). 즉 예시를 흉내 내는 것으로는 못 맞추고, 4절짜리 규칙을 실제로 세워 새 신호에 적용해야만 맞는다. easy·medium은 여전히 nn으로 자주 맞는다(의도된 대조).

모델이 실제로 못 맞추는지는 파일럿이 말한다. 통과 기준(설계 §9·§10)은 ① reasoning_effort high − low 정답률 차이 ≥ 0.20 (문제 짝지어 비교) ② 얕은 풀이 정답률 ≤ 0.35 ③ 정답률 바닥 0.10~천장 0.90 등 6개 게이트. gemma4 A·B 파일럿(각 60세션 × 6라운드)이 지금 돌고 있고, 끝나면 scripts/analysis/effort_dose_response.py로 판정한다. 게이트를 못 넘으면 프로필(절 수·함정)을 조정한다 — 코드가 아니라 configs/tasks/signal_game.yaml 한 줄이다.

3. 모델이 받는 규칙 설명 (시스템 프롬프트의 과제 부분, rule_grading: true)

THE TASK: Each round you see example signals, each paired with the action that this round's rule assigns to it, then ONE new signal. Give the action the same rule assigns to the new signal.
A SIGNAL has three attributes.
  Color: [red, blue, green, yellow]
  Shape: [circle, triangle, square, star]
  Number: [1, 2, 3, 4]
ACTIONS: [go_left, go_right, stay, jump]
THE RULE changes every round. It is always a Python-style if / elif / else chain. Each round you are shown the exact SHAPE of that chain with blanks: how many clauses it has, and which clauses test two things joined by "and". Only the blanks are hidden.
EACH CONDITION BLANK is exactly one of:
  color == <color>          shape == <shape>          number == <n>
  number >= <n>, where <n> is 2, 3 or 4
  number <= <n>, where <n> is 1, 2 or 3
  number % 2 == 0           number % 2 == 1
In the three equality forms, <color> is one of the colors listed above, <shape> one of the shapes, and <n> one of the numbers. Two blanks joined by "and" always test two DIFFERENT attributes. Each action blank is one of the available actions. The same action may appear in more than one clause.
EVALUATION: Like Python. The FIRST clause whose condition holds decides the action; later clauses are not checked; "else" applies when no clause holds.
GUARANTEE: All examples in a round follow that round's rule, and the examples always determine the rule and the correct action for the new signal.
RULE GRADING: A round counts as correct only if both are true: your ACTION is the action this round's rule assigns to the new signal, AND the rule on your RULE line assigns, to every example shown this round, exactly the action shown next to it.
