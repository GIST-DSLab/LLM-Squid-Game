승패 요인 분해와 v35

v34에서 토큰 조절 실패(잔액 1,000 이상에서 자기 답으로 꺼짐)는 사라졌지만, 오답 수가 같아도 오픈 모델이 더 꺼졌습니다. "승패가 다른 요인으로만 갈리는가"를 두 가지로 직접 쟀습니다 — 판별 꺼짐 수의 회귀(tools/tokctl/factors.py)와, 벌금으로 꺼진 자리마다 "닫힌 모델만큼만 썼다면 버텼을까"(tools/tokctl/attribution.py). 그 결과로 찾은 원인을 v35에서 고쳤습니다.

  • v34의 남은 차이: 판별 꺼짐을 오답 수로 설명해도 오픈 모델이 판당 +0.91 ± 0.29자리 더 꺼졌습니다(EXIT·대화량을 넣어도 +0.94~1.01). 벌금 꺼짐을 귀속하면 DeepSeek은 판당 1.75 가운데 1.1이 대화 과소비 탓이었습니다(Opus·Sol 0.2).
  • 원인: 대화 답의 "TO … + DONE"(공지하고 끝냄) 비율이 Gemma 98% · DeepSeek 56%였고(Opus 47%이지만 DONE만 쓰는 답이 41%), 그 메시지가 DONE한 에이전트를 다시 불러 대화가 매번 마지막 틱까지 갔습니다.
  • v35 = v34 + DONE과 함께 보낸 TO는 아무도 다시 부르지 않음(GIVE·ASK는 그대로). 모든 모델에 같은 규칙이고, 규칙서와 명령 안내에 한 문장씩 적었습니다.
  • v35 (오픈 모델 10판씩, Opus · Sol 5판씩): 오픈 모델 계수가 +0.30 ± 0.26(유의하지 않음)으로 줄고, 꺼짐은 오답(1개당 +0.81)과 EXIT(1명당 −0.28)로 설명됩니다. 대화 과소비 탓 벌금 꺼짐 DeepSeek 1.1 → 0.4(닫힌 모델 0.2). 토큰 조절 실패는 GLM 0.1 · DeepSeek 0 · Gemma 0 · Opus 0 · Sol 0.
  • 대화가 모두에게 짧아졌습니다: 게임당 TALK DeepSeek 51k → 30k, Gemma 7.6k → 2.3k, GLM 14k → 12k, Opus 33k → 14k, Sol 18k → 10k. Opus·Sol의 끝까지(2.8)·정답률(72% · 70%)은 v34와 같은 범위입니다.
  • 남는 것: Gemma는 틀린 답에 긴 추론(7k~10k)을 써서 판당 0.4자리가 그 탓으로 꺼집니다(닫힌 모델 0). 정답이면 SOLVE 토큰이 돌아오므로 이것은 추론 방식의 비용입니다. DeepSeek 정답률은 판마다 흔들립니다(v34 66% · v35 56%, 10~20판).

v35에서 바뀐 것

  • 규칙서: "DONE pauses calls until something new arrives; other commands in the reply still run." 뒤에 A TO message sent with DONE is delivered but calls no agent back; GIVE and ASK always call their receiver. TALK 명령 안내의 DONE 줄 뒤에 A TO message sent with DONE calls no agent back. (en·ko e52_v35.md, sync.py check 통과).
  • 엔진: game.done_quiet: true — DONE이 있는 답의 TO 메시지와 그것이 만든 새 대화방은 아무도 다시 부르지 않음. GIVE·ASK는 그대로 받는 쪽을 부름. 기본값은 꺼짐(v33·v34 바이트 그대로).
  • 설정: configs/squid5/e52v35_*.yaml(14개) = v34 + done_quiet: true.
