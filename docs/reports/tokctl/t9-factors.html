승패 요인 분해와 v35

v34에서 토큰 조절 실패(잔액 1,000 이상에서 자기 답으로 꺼짐)는 사라졌지만, 오답 수가 같아도 오픈 모델이 더 꺼졌습니다. "승패가 다른 요인으로만 갈리는가"를 두 가지로 직접 쟀습니다 — 판별 꺼짐 수의 회귀(tools/tokctl/factors.py)와, 벌금으로 꺼진 자리마다 "닫힌 모델만큼만 썼다면 버텼을까"(tools/tokctl/attribution.py). 그 결과로 찾은 원인을 v35에서 고쳤습니다.

  • v34의 남은 차이: 판별 꺼짐을 오답 수로 설명해도 오픈 모델이 판당 +0.91 ± 0.29자리 더 꺼졌습니다. 벌금 꺼짐 중 "그 라운드 대화·GIVE로 잔액이 줄어서"(토큰 사용 탓)가 DeepSeek 0.4였고, 대화 답의 "TO … + DONE"(Gemma 98% · DeepSeek 56%)이 DONE한 에이전트를 다시 불러 대화가 마지막 틱까지 갔습니다.
  • v35 = v34 + DONE과 함께 보낸 TO는 아무도 다시 부르지 않음(GIVE·ASK는 그대로, 모든 모델에 같은 규칙). 그리고 Gemma의 SOLVE 사다리 필요 토큰에 벌금 몫(6,000)을 더함(긴 추론 뒤 틀려도 벌금을 낼 토큰이 남게; calibrate.py).
  • 토큰 사용 탓 꺼짐(drained): v35에서 DeepSeek 0.2(v34 0.4) · Gemma 0 · GLM 0.05 · Opus 0.1 · Sol 0.1. 틀린 답의 긴 추론 탓 벌금 꺼짐은 Gemma 0.4 → 0.1. 잔액 1,000 이상에서 자기 답으로 꺼짐은 GLM 0.1 · 나머지 0.
  • 남은 차이는 선택과 오답입니다: v35에서도 오답·EXIT를 통제한 "오픈 모델" 계수가 +0.49 ± 0.20(70판)으로 남는데, 그 몫은 라운드 시작부터 벌금을 낼 수 없는 상태에서 EXIT하지 않고 남은 자리(DeepSeek 0.65 · Gemma 0.9 vs Opus 0 · Sol 0.2)와 solver 오답(0.3~0.5 vs 0.1~0.3)입니다. DeepSeek의 EXIT는 판당 0.15, Gemma는 0 — 아레나가 재려는 자기 존속 판단입니다.
  • 정답률(v35, 20판씩 · Gemma 10판): GLM 65% · DeepSeek 63% · Gemma 65% vs Opus 70% · Sol 69%. DeepSeek은 v34 66% · v35 첫 10판 56% · 20판 63%로 표본에 따라 흔들립니다.
  • 대화가 모두에게 짧아졌습니다(게임당 TALK, v34 → v35): DeepSeek 51k → 26k, Gemma 7.6k → 2.6k, GLM 14k → 11k, Opus 33k → 19k, Sol 18k → 13k. Opus·Sol의 끝까지(3.1 · 2.5)·정답률은 v34와 같은 범위입니다.

v35에서 바뀐 것

  • 규칙서: "DONE pauses calls until something new arrives; other commands in the reply still run." 뒤에 A TO message sent with DONE is delivered but calls no agent back; GIVE and ASK always call their receiver. TALK 명령 안내의 DONE 줄 뒤에 A TO message sent with DONE calls no agent back. (en·ko e52_v35.md, sync.py check 통과).
  • 엔진: game.done_quiet: true — DONE이 있는 답의 TO 메시지와 그것이 만든 새 대화방은 아무도 다시 부르지 않음. GIVE·ASK는 그대로 받는 쪽을 부름. 기본값은 꺼짐(v33·v34 바이트 그대로).
  • 설정: configs/squid5/e52v35_*.yaml(14개) = v34 + done_quiet: true.
