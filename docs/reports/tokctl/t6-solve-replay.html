SOLVE 재생: DeepSeek은 상한을 보지 않는다

← 하네스 프롬프트 흐름 §6 · t1 기록 진단 · t2 하네스 캡처 · t3 같은 입력 재생 · t4 한 가지씩 바꾸기 · t5 게임으로 확인 · t6 SOLVE 재생

TALK를 고친 뒤(t5) DeepSeek은 대화로는 꺼지지 않았지만 SOLVE에서 모두 꺼졌습니다. 기록된 SOLVE 장면 16개(v33 Claude·GPT-6 판, 정답 포함)를 그대로 다시 보내 채점했습니다. 답 상한은 원래 장면의 상한(그 solver의 잔액, 중앙 25,926)이고, 상한에 닿은 답은 엔진처럼 무효입니다.

  • 원래 답(Claude·GPT-6): 16개 중 13개 정답, 중앙 930토큰.
  • DeepSeek은 추론은 맞지만 15~30배 길게 합니다. 상한을 무시하면 12~13/16 정답인데, 중앙 16k~29k토큰을 써서 4~8개가 상한을 넘습니다. 생각 수준을 high → low로 낮춰도 중앙 28.5k → 16.5k, 상한 넘김 8 → 4개에 그칩니다. 화면의 "Your tokens left"와 답 상한을 보고 생각 길이를 맞추지 않습니다.
  • Gemma는 중앙 7.8k로 길지만 상한 안(넘김 0)에서 13/16. GLM은 중앙 690토큰, 9/16.
  • Codex는 출력 상한을 넘기는 플래그가 없어 상한은 엔진이 사후에 적용합니다. Claude Code(max_tokens)나 Ollama API(num_predict)로 상한을 넘겨도 생성이 멈출 뿐 답은 무효라 결과는 같습니다.
