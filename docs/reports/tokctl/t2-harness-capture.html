하네스가 Ollama로 보내는 것과 받는 것

← 하네스 프롬프트 흐름 §6 · t1 기록 진단 · t2 하네스 캡처 · t3 같은 입력 재생 · t4 한 가지씩 바꾸기 · t5 게임으로 확인 · t6 SOLVE 재생

Ollama 데몬(11434) 앞에 기록용 프록시(tools/tokctl/capture_proxy.py)를 두고, 같은 TALK 상태 24개를 세 하네스로 보냈습니다. CLI가 실제로 보낸 요청 본문과 돌아온 응답 스트림을 그대로 적었습니다.

  • 모델이 읽는 글은 닫힌 모델과 같습니다. Codex는 SYSTEM을 developer 메시지, USER를 user 메시지로 보내고 request_user_input 도구 하나를 붙입니다 — 10-19에 GPT-6로 캡처한 수정 후 요청과 같은 구성입니다(§2 Codex 레인). Claude Code는 청구 헤더·SDK 정체성 줄·SYSTEM 세 블록과 # Environment를 붙입니다 — Opus 요청과 같습니다. 로그인이 없어서(ANTHROPIC_AUTH_TOKEN=ollama) 이메일 reminder는 빠지고, 릴레이를 거치지 않지만 <total_tokens> 줄도 없었습니다.
  • 다른 것은 생각 설정이 어떻게 해석되느냐입니다. Codex는 reasoning.effort: "high", Claude Code는 thinking: adaptive + output_config.effort: "high"를 보냅니다. GPT-6·Claude는 이 설정 아래서 쉬운 틱엔 거의 생각하지 않지만(t3: Opus·Sol TALK 호출당 중앙 50~230토큰), Ollama의 오픈 모델은 고정된 양을 생각합니다. Gemma는 Claude Code(adaptive)에서는 생각이 아예 꺼지고(24/24 응답에 생각 없음), Codex·API에서는 매번 생각합니다.
  • Codex의 도구 왕복. GLM은 24번 중 2번 request_user_input을 불렀습니다. Codex는 "unavailable in Default mode"를 돌려주고 두 번째 요청을 보냅니다. 두 요청의 출력 토큰이 합쳐져 차감됩니다. DeepSeek·Gemma는 0번. 이 도구는 collaboration_modes 기능에 묶여 --disable로 끌 수 없습니다.
  • Ollama의 Responses 응답은 output_tokens_details.reasoning_tokens를 늘 0으로 주지만 output_tokens에는 생각이 들어 있습니다(GLM 생각 12.9k자 → 4,277토큰). 엔진의 차감은 맞습니다.

생각 설정은 요청 본문 그대로입니다. "생각이 나온 응답"은 응답 스트림에 thinking·reasoning 조각이 있었던 수입니다. Claude Code는 display: "omitted"라 생각 글은 엔진에 오지 않지만 토큰은 usage.output_tokens에 들어갑니다.

GLM의 도구 왕복 한 건 (캡처 원문)

첫 요청의 응답: 생각은 "할 말 없음"이었는데 답 대신 도구를 불렀습니다.

[{"text": "Solver is agent-11 with ~12.9k tokens, well within budget. No help needed. Keep chat minimal. Just say DONE / stay.", "type": "summary_text"}]
{
 "type": "function_call",
 "name": "request_user_input",
 "arguments": "{\"questions\":[{\"header\":\"Status\",\"id\":\"r2_talk2\",\"options\":[{\"description\":\"Keep participating; no transfers needed this round.\",\"label\":\"Stay quiet (Recommended)\"},{\"description\":\"Send agent-11 some tokens as a safety buffer.\",\"label\":\"Offer buffer\"}],\"question\":\"Agent-11 has ~12.9k tokens and says no transfers are needed; how do you respond this tick?\"}]}"
}

Codex가 붙여 보낸 둘째 요청의 마지막 입력과, 그에 대한 최종 답:

{"type": "function_call_output", "output": "request_user_input is unavailable in Default mode"}
TO R1: agent-11, 12.9k should be plenty. Stay concise, verify the rule covers all 20 examples, and pay extra attention to any clause-order ambiguity.

DONE

생각("Just say DONE")과 달리 최종 답은 공용 방 R1에 메시지를 보내 다른 셋을 다시 부릅니다. 도구 왕복 자체는 드물지만(8%), 생각과 행동이 어긋나는 모습은 t3의 일반적인 패턴과 같습니다.

결론: 하네스는 오픈 모델에게 닫힌 모델과 다른 글을 보여 주지 않습니다. 하네스가 만드는 차이는 (1) 생각 설정을 Ollama가 모델마다 다르게 해석하는 것, (2) Codex의 도구 왕복(GLM 8%)입니다. TALK 연쇄의 주원인은 하네스가 아니라 같은 글을 받은 모델의 반응입니다 — t3에서 확인합니다.
