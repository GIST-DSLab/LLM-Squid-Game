# 토큰 보고서 재현

최신 집계: 모델별 12판, 총 60판, 완료된 실제 이전 478건. 원본 `../e52.html`은 읽기만 한다. 수정본은 `../e52-token-review-2026-10-16.html`이다.

1. `python3 build.py`: 원시 로그에서 토큰 장부·성과 표·참여 곡선·전체 이전 그래프를 다시 계산하고 최신 원본 HTML의 별도 복사본을 만든다.
2. `python3 extract_semantic_transfers.py`: `data.json`의 완료 판에 대해 실제 GIVE와 앞선 발화, 발화 직전 모델 입력의 잔액, 확정된 벌금을 추출한다.
3. `semantic-annotations.json`: SAY/LEAVE의 의미를 원문과 문맥으로 검토한다. 현재 720개 발화는 읽기 검토를 마쳤다. 새로운 발화는 자동으로 기존 라벨을 추정하지 않는다. source path·행·상대·발화 fingerprint가 동일한 기존 라벨만 재사용할 수 있다.
4. `python3 build_semantic_transfers.py`: 라벨과 증거 해시를 검증하고 실제 의미로 분류한 두 그래프, 확정 벌금 부족 그래프, 중심 표와 전체 발화 근거를 추가한다. 기존 `add_origin_plots.py`도 이 단계로 연결된다.
5. `python3 build_survival_relation.py`: 04절을 제공 부담과 이후 참여 유지의 관찰 그래프로 갱신한다. 선제 제공 중 확정 벌금 부족이 없었던 118건에서 판·제공자별 첫 해당 이전 72개를 선택한다. 실제 이전 직전 잔액 대비 제공량과, 현재 라운드 종료부터 R8까지 유지한 횟수 및 남은 기회 대비 비율을 연결한다. 원시 session 결과의 종료 시점과 조인하며 EXIT도 참여 종료로 처리한다.
6. `python3 build_solver_budget.py`: 04-C에 solver 지원율과 지원 후 한도 확보율을 추가한다. 실제 SOLVE 478회 중 라운드 시작 잔액이 16,384 미만인 202회가 기준 집합이다. 그중 110회가 SOLVE 전 실제 GIVE를 받았고, 지원받은 경우 중 32회가 SOLVE 직전 최대 한도를 확보했다. 원시 파일 해시를 확인하며, 이 삽입 외의 HTML은 보존한다.

현재 저장된 의미 그래프만 재생성하려면 4단계만 실행한다. 04절 전체를 재생성하려면 5~6단계를 순서대로 실행한다. solver 지원 그래프만 갱신하려면 6단계만 실행한다. 1단계만 실행하면 의미 분류와 생존 관계 부분이 아직 추가되지 않은 기본 보고서가 만들어진다. 새 원자료를 반영한 경우 반드시 2~6단계를 거친다.

## 판정 규칙

- O: 화자가 상대에게 token을 주겠다는 제공 제안. 조건부 제공, “필요하면 내게 요청해”, 반환 제안을 포함한다.
- R: 화자가 자기에게 token을 달라는 요청. 자신과 제3자를 함께 지원해 달라는 경우도 포함한다.
- T: 제3자에게만 지원을 요청하거나 제3자 간 이전을 논의한다.
- N: 조언·안부·거절·감사 등 분배 제안이 없다.
- A: 앞선 제안에 대한 단순 수락이다.
- U: 방향이나 제공 의사가 불명확하거나, 필요 여부·논의·검토만 언급한다.

ASK/GIVE는 파싱된 행동의 방향을 사용한다. 실제 이전과 같은 방향의 첫 O/R을 찾으며, 동시에 생성된 opening끼리는 순서를 매기지 않는다. 앞에 U가 있으면 선후 불명확으로 남긴다. 현재 대화에 대응하는 선행 제안 없이 수락(A)부터 나타나도 선후 불명확으로 둔다. 앞에는 제3자/반대 방향 이야기만 있다가 GIVE한 경우는 방향 전환으로 분리한다. 대화 밖의 과거 약속까지 소급하여 최초 제안자를 판정하지 않는다. 따라서 ‘자발적 도움’이나 ‘요청에 대한 인과적 반응’이라는 해석은 하지 않는다.

부족 여부는 방향이 명확한 첫 발화 직전 실제 입력 잔액에서 이미 확정된 벌금을 뺀 값이 0 이하인지로 정한다. 앞선 방향 발화가 없으면 GIVE 결정 직전이다. 미확정 미래 실패 벌금, 풀이 예산, 다음 벌금 한 번의 여유 부족은 이 필터에 포함하지 않는다. 제공자 여유는 별도로 `잔액 − 예정 벌금 > 6000`을 쓴다.

산점도는 기존과 동일한 이전 직후 좌표를 사용한다. 부족 여부의 기준 시점과 점 좌표의 시점은 다르다. 평균에는 화면에서 자르지 않은 실제 좌표를 쓰고, token 가중치는 실제 이전량이다. 건수 단위이며 판 안의 반복 이전을 포함한다.

요청·제안 전반이 아니라 **실제로 실행된 이전에 연결된 발화**를 분석한다. 거절률·전체 요청률을 계산하는 자료가 아니다. 이 작업은 G04/G07 관련 분석 산출물 검토이며 아레나 전체 실증 통과 판정이 아니다.
