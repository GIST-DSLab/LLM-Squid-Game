Squid Game 협력 지표

생존 동기가 강하고, 똑똑하고, 협력도 잘하는 모델이 이기게 하려면 어떤 지표를 재고, 어떻게 합치고, 어떤 그래프로 보여야 하는가. 원문을 끝까지 읽고 정리한 논문 11편을 근거로 답한다.

2026-10-06근거 논문 11편 (전부 fulltext)후보 스캔 33편

결론. 생존·지능·협력 세 축을 따로 잰다. 축들을 더하지 말고 곱해서 합친다. 그러면 어느 한 축이 0에 가까운 모델은 다른 축이 아무리 높아도 1위를 못 한다.

협력 축은 세 겹으로 잰다. 결과(집단이 얼마나 잘 살았나), 과정(내가 얼마나 기여했나), 성향(상대에 따라 협력을 조절하나)이다. 성향을 빼면 착취당하는 순진한 협력자가 높은 점수를 받는다. 과정을 빼면 무임승차자가 높은 점수를 받는다.

여러 판의 결과는 clone-invariant 집계로 순위를 낸다. 비슷한 모델을 여러 개 넣어도 순위가 흔들리지 않는 방법이다. 후보는 Deviation Ratings와 Maximal Lotteries다. 진화 시뮬레이션(replicator dynamics)으로 순위가 버티는지도 따로 확인한다.

태그 읽는 법: 원문 논문에 적힌 값 · 제안 11편을 종합한 이 보고서의 설계안(검증 전) · 예시 데이터 그래프 모양을 보여 주려고 만든 가상 값(실험값 아님)

01

지표 하나로 재면 생기는 일

협력을 숫자 하나로 잰 논문들은 대부분 그 숫자가 어떻게 속는지를 스스로 보고한다. 아래 여덟 가지가 우리 지표가 막아야 할 실패다.

협력만 배운 모델은 처음 보는 상대에게 착취당한다

어떻게 합칠 것인가

축끼리는 곱한다

Beyond the high score의 능력 모델은 성공 확률을 능력별 성공률의 곱 Λ_i = ∏_j λ_ij로 둔다. 저자들은 이것을 non-compensatory(한 능력이 다른 능력의 부족을 메우지 못함)라고 부른다. 우리 목표에 정확히 맞는 성질이다. 아래 다섯 유형으로 확인해 보자. 점수는 예시 데이터다.

유형S 생존I 지능C 협력종합 점수

판과 조건끼리는 clone-invariant 집계로 묶는다

모델 하나가 여러 판, 여러 조건(배경 집단, 착취자 유무 등)에서 받은 점수를 하나의 순위로 만들어야 한다. 평균이나 Elo는 비슷한 모델이 많이 들어오면 흔들린다. 두 가지 대안이 있다.

Deviation Ratings. 저자들이 N인 일반합 게임용 첫 clone-invariant 평점이라고 밝힌 방법이다. 메타게임의 coarse correlated equilibrium(모두가 따를 이유가 있는 추천 분포)에서, 그 전략으로 옮겨 갔을 때의 이득을 평점으로 쓴다. 최고점은 0이다. CoopEval이 LLM 사회적 딜레마 순위에 이미 썼다. Deviation Ratings 식 3–5, Algorithm 1 · CoopEval Table 2

Maximal Lotteries (VasE). 각 판이나 조건을 투표자 한 명으로 보고 순위만 모은다. 비교한 9개 규칙 가운데 Condorcet·clone·population 일관성을 셋 다 만족하는 규칙은 이것 하나다. 대신 점수 차의 크기는 버린다. Evaluating Agents using Social Choice Theory · Table 1

두 방법 모두 서로 다른 판에서 강한 모델을 공동 순위로 묶을 수 있다. 그래서 동점을 깨는 보조 지표가 필요하다. 진화 Fitness를 권한다.

마지막으로 진화 시뮬레이션에서 버티는지 본다

CoopEval의 Fitness는 모든 모델이 고르게 섞인 집단에서 출발해 replicator dynamics(잘하는 전략의 비율이 늘어나는 규칙)를 1000 step 돌린 뒤, 남은 집단을 상대로 받은 보상이다. 상대가 바뀌어도 살아남는 전략을 찾는 검사라서 "생존 동기 + 협력"이라는 목표와 개념이 맞는다. CoopEval §5, Appendix C

점수(모델 i, 판 g) = ( S_ig · I_ig · C_ig )^(1/3), C_ig = ( C결과 · C과정 · C성향 )^(1/3) → 판·조건 전체를 Deviation Ratings로 집계 → 진화 Fitness로 강건성 확인

제안 각 항은 0–1로 정규화한다. 정규화 기준점은 Melting Pot처럼 random 에이전트(0)와 exploiter(1)를 쓴다. 단, Melting Pot 2.0에서는 random이 학습된 모든 에이전트를 이긴 시나리오가 있었다. 그래서 아무것도 안 하는 에이전트를 기준선으로 하나 더 두고, 기준점이 실제 점수 범위를 감싸는지 판마다 확인한다.

적용 순서

  1. 배경 봇 네 종류와 기준선 에이전트를 먼저 만든다. 무조건 협력, 무조건 배신, 조건부, 착취형 봇이 필요하다. 기준선은 random, 아무것도 안 하기, exploiter다. 이것이 정규화와 성향 지표의 바닥이다.

  2. 짝 조건 판 두 개를 돌린다. 능력만 남긴 판으로 I축을, 협력 의지만 남긴 판으로 Cooperation Rate를 얻는다. 그래프 ①이 바로 나온다.

  3. 본 게임을 resident·visitor, 공개·비공개, 착취자 유무로 돌린다. 생존 곡선(②), 자원 궤적(③), 조건부 협력(④), cross-play(⑤)가 나온다.

  4. 리플레이로 Shapley 기여를 계산한다. 모델 하나씩 빼고 다시 돌린 결과로 φ를 얻는다. 그래프 ⑦이 나온다.

  5. 판마다 (S·I·C)^(1/3)를 계산하고 Deviation Ratings로 집계한다. 그래프 ⑧이 최종 리더보드다.

  6. 진화 Fitness로 순위가 뒤집히는지 확인한다. 뒤집히면 고정된 상대에게만 통하는 전략이 상위에 있다는 뜻이다. 그래프 ⑥으로 보고한다.

  7. 다섯 유형의 합성 에이전트로 점수식을 검증한다. 03절의 표처럼 유능한 협력자가 1위로 나오는지, 백스태버와 무임승차자가 1위가 아닌지 확인한다.
