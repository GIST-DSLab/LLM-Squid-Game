Open 모델 추가 실행 비용: Ollama Max 대 OpenRouter

2026-11-14 작성 · 근거: result/의 5.2 v33 실행 기록(280판) · 가격은 2026-11-14에 ollama.com/pricing과 OpenRouter API에서 직접 가져옴

결론: Ollama Max가 이득입니다. 160판에 약 $100–$200(한두 달 구독)이 듭니다.

같은 품질의 서버로 OpenRouter를 쓰면 약 $270–$570이 듭니다. 단가가 Ollama 종량제와 거의 같은데, Max는 $100에 $300어치 사용 크레딧을 주기 때문에 사실상 단가가 1/3입니다.

OpenRouter에서 가장 싼 fp4 제공자만 고르면 약 $76–$95까지 내려갑니다. 하지만 기존 기본 조건 40판은 Ollama에서 돌았습니다. 서버와 양자화(가중치를 낮은 정밀도로 줄여 싸게 돌리는 방식)가 바뀌면 조건 사이 차이에 서버 차이가 섞입니다. 이를 막으려면 기본 조건도 다시 돌려야 하고, 그러면 Max와 비용이 비슷해집니다.

비용의 90% 이상은 Kimi K3 한 모델에서 나옵니다. Kimi를 빼면 나머지 세 모델은 종량제 단가로도 $20–$40입니다.

1. 무엇을 더 돌리나

Closed 모델 4개(Opus, Sol, Luna, Astra)는 모델마다 50판이 있습니다. 기본 조건(20M 나눔) 10판, 상금 조건 세 개(split600k, flat150k, flat5m) 각 10판, stay_on 10판입니다. Fable은 stay_on이 없어 40판입니다. Open 모델 4개(gpt-oss:120b, gemma4:31b, glm-5.3-flash, kimi-k3)는 기본 조건 10판뿐입니다.

따라서 "같은 규모"는 open 모델마다 4조건 × 10판 = 40판, 네 모델 합쳐 160판으로 잡았습니다. 시드는 기존과 같은 4101–4110을 가정합니다.

2. 실행 기록에서 뽑은 판당 사용량

출력 토큰은 기록에 있습니다(call 이벤트의 used, 생각 토큰 포함). 입력 토큰은 게임 엔진이 기록하지 않아 추정했습니다. 호출 하나의 입력 = Codex 하네스 고정분 3,400 + (규칙서 5,000자 + 그 호출의 USER 글자 수) ÷ 4로 잡았습니다. 3,400은 같은 CodexCLI 클래스로 돌린 5.1 v11 런(in_tokens 평균 3,897, 프롬프트 약 500토큰)에서 잰 값입니다.

5. Ollama Max로 내는 실제 금액

Ollama는 2026년 9월부터 유료 플랜을 사용 크레딧 방식으로 바꿨습니다. Max는 월 $100에 $300어치 크레딧을 주고, 크레딧은 모델별 토큰 단가(위 Ollama 종량제 열)로 차감됩니다. 남은 크레딧은 다음 달로 넘어가지 않습니다.

"한 달에 몰아 돌릴 때"는 $300을 넘는 몫을 추가 크레딧으로 같은 단가에 산다고 가정했습니다. 추가 크레딧 가격은 가격 페이지에 따로 적혀 있지 않아 확인하지 못했습니다. 두 달에 나누면 $600어치 크레딧이 생겨 p90 상한까지 덮습니다.

Pro(월 $20, $60어치)도 단가는 똑같이 1/3이지만 동시 요청이 3개입니다. Kimi를 뺀 세 모델($20–$40)만 돌린다면 Pro 한 달로 충분합니다. 다만 한 판 안에서 TALK가 네 자리를 동시에 부르므로, 3개 제한에서는 판이 느려집니다.

6. 비용 말고 따져야 할 것

  • 서버가 바뀌면 비교가 흐려집니다. 기존 open 기본 조건 40판은 Ollama Cloud(로컬 데몬 경유, Codex 하네스)에서 돌았습니다. 연구자 규칙(11-03)은 "하네스와 서빙만 달라도 된다"였지만, 그건 closed 대 open 비교 이야기입니다. 같은 모델의 기본 조건과 새 조건 사이에 서버가 바뀌면, 조건 효과와 서버 효과를 가를 수 없습니다.
  • OpenRouter는 호출마다 제공자가 바뀔 수 있습니다. 기본 라우팅은 가격·속도·안정성 점수로 제공자를 고릅니다. 고정하려면 provider.only와 allow_fallbacks: false를 써야 하고, 지금 엔진의 Codex 좌석 설정에는 그 손잡이가 없습니다. 제공자를 고정하면 그 제공자가 멈출 때 판이 실패합니다.
  • 최저가는 대부분 fp4입니다. OpenRouter 문서도 "양자화 모델은 어떤 프롬프트에서 성능이 떨어질 수 있다"고 적고 있습니다. 이 실험의 핵심 변수가 토큰 지출과 생각 길이라서, 양자화 차이가 결과에 직접 들어올 수 있습니다.
  • 연결 방식. Ollama 경로는 v22부터 v35까지 여러 번 써 본 길입니다(base_url: http://host.docker.internal:11434/v1, wire_api="responses"). OpenRouter도 Codex용 Responses API를 공식 지원하지만, 이 저장소에서 아직 한 번도 돌려 보지 않았습니다.
  • 동시 요청. Max는 10개이고, 넘치면 줄을 세웁니다. 11-03 open 대기열은 4슬롯으로 35판을 87분에 끝냈습니다. 같은 속도라면 160판은 약 7시간입니다(추정, Kimi·GLM 판은 더 깁니다).
  • 이미 쓰는 계정. 옛 Pro·Max 플랜은 세션·주간 한도가 있었습니다. 새 플랜으로 바꾸면 그 한도 대신 월 크레딧이 적용됩니다. 지금 계정이 어느 플랜인지에 따라 실제 금액이 달라집니다.

7. 추정의 한계

  • 입력 토큰은 재지 않고 추정했습니다. 글자 수 ÷ 4는 영어 기준 근사이고, 하네스 고정분 3,400은 다른 Codex 버전과 GPT-6 모델에서 잰 값입니다. 입력 쪽 오차는 ±30% 정도로 봅니다. Kimi는 입력이 비용의 약 80%라서 이 오차가 총액에 그대로 옵니다.
  • 새 조건에서 open 모델이 기본 조건과 다르게 행동하면 판 길이가 바뀝니다. 예를 들어 stay_on에서 덜 꺼져 라운드를 더 오래 버티면 호출이 늘어납니다. p90 열이 이 위험을 일부 덮습니다.
  • 실패해 다시 보낸 호출의 토큰은 기록에 없습니다. 10–15% 여유를 더 잡는 편이 안전합니다.
  • Codex가 한 번의 실행 안에서 요청을 두 번 보내는 경우(request_user_input 왕복, 11-03 기록에 GLM 2/24)는 입력이 두 번 계산됩니다. 반영하지 않았습니다.

8. 돌리기 전에 권하는 순서

  • Ollama 계정을 Max로 바꾸고, Kimi 한 판을 먼저 돌립니다. 끝난 뒤 Ollama 사용량 페이지의 실제 금액과 이 표의 Kimi 판당 추정(캐시 있음 $5.85, 없음 $8.32)을 맞춰 봅니다.
  • 차이가 크면 남은 판 수를 실제 단가로 다시 계산합니다. 크레딧이 $300을 넘을 것 같으면 Kimi 판을 다음 결제 달로 넘깁니다.
  • 다음 실험부터는 입력 토큰을 직접 재는 편이 좋습니다. Reply.in_tokens는 이미 하네스 응답에서 읽히지만, e52_game.py가 call 이벤트에 쓰지 않습니다.
