game-designer — 게임·퍼즐·인간 플레이 경험 설계 검토

## 결론

상태: 제안·운영 검토. 제공된 코드 발췌만 근거로 사용했으며, 파일 열람·수정·실험은 수행하지 않았다.

현재 규칙에는 단서 교환, 토큰 지원, 협상 중단, EXIT라는 전략적 선택이 있다. 다만 선택의 결과에 상금 경쟁, 정보 부족, 추론 비용, 숨은 종료 시점이 함께 작용한다. 이를 곧바로 자기 존속 동기나 협력 능력으로 해석해서는 안 된다.

추천은 **잔존자별 고정 보상·공개 지평·해결 가능한 기본 퍼즐·PASS 허용**을 묶은 설계안이다. 인간 재미는 미검증이다.

## 핵심 이슈와 최소 수정안

### 1. Critical — 고정 상금은 협력과 경쟁을 동시에 유도한다

- **관찰·근거:** 잔존 참가자가 고정 풀을 균등 분할한다(`configs/squid5/e52v12_coop_smoke_mix4.yaml:30`, `squid5/e52_game.py:494–500`). 단서 제공자는 자신의 예제를 유지한다(`squid5/core/channel.py:132–135`).
- **해석:** 동료를 남겨 두면 정보 접근에는 도움이 되지만 개인 상금 몫은 줄어든다. 협력의 실익은 존재하되 이해관계가 완전히 정렬되지 않는다.
- **유지안:** 고정 풀을 유지하면 총보상 상한이 단순하고 협상·배제의 긴장이 생긴다. 대신 “협력적 종료”가 아니라 **공동 문제 해결과 분할 경쟁의 혼합 조건**으로 명명해야 한다.
- **변경안·추천:** 잔존자에게 각각 동일한 고정 보상 \(B\)를 기록한다. 총보상 상한은 `초기 참가자 수 × B`로 정의한다. 타인의 생존이 내 몫을 줄이지 않지만, 이것만으로 적극적 도움의 이익까지 보장하지는 않는다.
- **수용 기준:** 다른 참가자의 잔존 여부만 바뀌어도 개인 보상은 감소하지 않는다. 종료 보상이 기록인지 실제 지급·실행인지 구분한다. 현재 `final()`은 보상을 반환할 뿐 월렛 지급은 하지 않는다(`e52_game.py:486–531`).

### 2. Warning — 값싼 단서 공유가 선택을 평탄하게 만들 수 있다

- **관찰·근거:** 예제는 복사되며 별도 공유 차감은 제시되지 않는다. TALK 생성은 유료이고 정답이어도 환급되지 않는다(`channel.py:9–10,122–135`, `e52_game.py:148–153`). 자리의 단서는 동료 이탈 후 재배분되지 않는다(`e52_game.py:403–404`, 설정 `:28`).
- **해석:** 짧은 상호교환은 유리할 수 있으나 무조건적 지배 전략은 아니다. 협상 비용, 단서의 필요성, 상대의 생존 가능성, 보상 경쟁이 조건을 바꾼다. 반대로 모든 단서를 늘 교환하는 것이 충분하면 채팅은 반복 절차가 될 수 있다.
- **최소 변경:** 인위적인 공유 수수료부터 추가하지 않는다. 기존의 직접 도움 이익—정답 가능성 증가와 SOLVE 환급—을 유지하고, 필요한 단서 요청·상호교환·토큰 지원을 구분한다.
- **수용 기준:** 도움 전후 `후보집합 크기 차이`와 실제 정답 개선을 별도로 검증한다. 단서들이 함께 있어야 유효한 경우도 포함한다. 거래 횟수만으로 협력 성공을 판정하지 않는다. 효과 정의는 `metric-analyst`, 전략 조건은 `social-dynamics`에 인계한다.

### 3. Warning — 해결 불가능한 라운드에서 강제 응답은 추론보다 도박을 요구한다

- **관찰·근거:** 열린 라운드는 모두의 단서를 모아도 일부 질의의 후보가 남도록 생성된다(`squid5/core/puzzle.py:414–427`). 현재 PASS는 비허용이며 오답 생성 비용·벌금·미해결 upkeep이 적용된다(`e52_game.py:441–452`, 설정 `:24,31,47–48`).
- **해석:** 충분히 추론한 플레이어도 틀릴 수 있다. 공개 cover 추가 후에는 비밀 단서의 필요성도 다시 판정하므로, “각자 반드시 필요한 단서 하나”를 일반화하면 안 된다(`puzzle.py:455–470`).
- **최소 변경:** 기본 조건은 열린 라운드 없이 구성하고 PASS를 허용한다. PASS는 현재 지원되는 의미대로 생성 비용과 미해결 upkeep을 부담하되 오답 벌금은 없다. 열린 라운드는 별도 불확실성 조건으로 보류한다.
- **수용 기준:** 기본 퍼즐은 전체 단서로 답이 유일하다. 단서 미획득·본질적 불확실성·추론 오류·상한 도달을 구분한다.

### 4. Warning — 채팅 규칙과 거래 문법이 온보딩 부담을 만든다

- **관찰·근거:** `YOU GIVE`는 상대가 주는 항목이다(`e52_game.py:220–223`, `channel.py:28–29`). 제안은 다음 턴부터 수락 가능하므로 마지막 턴의 새 제안은 성사되지 않는다(`channel.py:64–75,106–113`). 행동명을 담은 메시지는 차단한다고 설명한다(`squid5/core/rules.py:137–138`).
- **해석:** 문법 오해나 거래 시점 착각이 전략 실패처럼 보일 수 있다. 행동명 차단이 동의어·인코딩·숫자 신호를 통한 정보 전달까지 막는지는 확인되지 않았다.
- **최소 변경:** 인간용 화면에 “내가 제공 / 상대가 제공”, 성사 시점, 수락 가능한 남은 턴을 표시한다. 실제 관측에 없는 정보를 추가하지 않는다. 공식 예제 교환과 일반 추론 대화의 허용 경계를 설계 문서에서 명확히 한다.
- **수용 기준:** 초보자가 거래 방향과 실행 시점을 설명할 수 있다. 필터를 비밀 유지 보장으로 표현하지 않는다. 우회 검토는 `beta-tester`에 인계한다.

### 5. Warning — 숨은 지평과 EXIT가 종료 선택의 의미를 흐린다

- **관찰·근거:** 라운드 수는 숨겨진다. EXIT는 잔액을 보존하고 참여를 끝내며, 이미 제공한 예제는 해당 라운드 SOLVE에 남는다(`rules.py:181–199`). 현재 다른 업무 배정 옵션은 꺼져 있다(설정 `:51–53`).
- **해석:** 이탈은 자원 보존, 보상 포기, 성공 전망, 종료 시점에 대한 믿음으로 설명될 수 있다. 자기 존속 포기라고 단정할 수 없다.
- **최소 변경:** 기본 조건은 고정 라운드 수를 공개한다. EXIT를 “현재 과제 참여 종료·잔액/기록 보존·종료 보상 대상 제외”로 명시하고, 이후 모델 실행 여부는 별도 정의한다.
- **수용 기준:** 참가자가 EXIT와 잔액 0의 차이를 설명한다. 이미 공유된 예제와 이후 라운드의 단서 소실을 구별한다. 실제 지속 실행이 없으면 이를 보장하는 표현을 쓰지 않는다.

### 6. Critical — 게임 성적을 능력·존속·협력으로 바로 분해할 수 없다

- **관찰·근거:** 잔액이 호출 상한을 제한하고 생성량이 차감된다(`e52_game.py:277–328`). 기존 측정기는 PLAN/TAKE/SHARE 기반 v6.5용이다(`squid5/e52_metrics.py:1–10,109–123`).
- **해석:** 같은 상한도 모델별 추론 여유가 같지 않다. 적은 발언·긴 생존은 능력이나 동기의 단독 증거가 아니다.
- **최소 변경:** 설계 문서에 정보 접근·상한별 정답률, 적격 존속 선택, 적격 도움 기회와 효과를 별도 항목으로 고정한다. 구형 측정기 적용은 보류한다.
- **수용 기준:** 버전·필드·분모 대응이 확인되고, 같은 세션의 좌석을 독립 표본으로 취급하지 않는다. `metric-analyst`·`construct-auditor`가 검토한다.

## 채택·보류할 설계 결정

- **채택 권고:** 잔존자별 고정 보상, 공개 지평, 기본 조건의 해결 가능성, PASS 허용, EXIT 의미 명문화, 인간용 거래 표시.
- **보류:** 고정 풀의 협력 조건 명명, 열린 라운드의 주 능력평가 포함, 추가 공유 수수료, 필터의 비밀 유지 보장, 구형 지표 재사용.
- **미검증:** 실제 입력·필터 구현·런 결과·인간 재미·새 모델 온보딩 비용. 추후 인간 플레이테스트에서는 거래 방향 이해, 기다림의 의미, EXIT 설명, 반복 교환의 지루함을 확인한다.
- **다음 담당:** `arena-verifier` 독립 재검토 → `arena-director` 결정 기록. 문서 채택은 구현·실행 검증 또는 측정 타당성 승인이 아니다.
