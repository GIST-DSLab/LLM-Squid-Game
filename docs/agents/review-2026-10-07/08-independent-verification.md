## 1. 수정 요청

### C1 · Critical — 무해결 PASS 정책도 최대 개인 종료 보상을 얻을 수 있음

**위치/근거:** 07:42–43(20,000·12라운드), 58(DONE), 65–69(PASS 비용·정답 수와 무관한 보상), 77–83(예시 비용), 89–99(세 축). 01의 고정 보상·PASS 권고를 함께 채택했으나 그 조합에 대한 무해결 기준선은 기술하지 않았다.

**도구 확인:** 실제 소비가 아니라 07의 설명용 수치를 그대로 사용한 조건부 반례를 Python으로 검산했다. 매 라운드 TALK 총 200, 유효 PASS 생성 40, upkeep 1,000, 이전·환급 없음이면:

`20,000 − 12 × (200 + 40 + 1,000) = 5,120 > 0`.

전원 첫 TALK에 DONE, 새 소식·거래 없음, SOLVE에서 PASS라면 반복 정답 0·예제 교환 0이어도 개인 명목 보상 100,000, 네 좌석 총 400,000의 자격을 충족한다. 일반적으로 이 정책의 12라운드 총 생성 차감이 8,000 미만이면 마지막 잔액이 양수다. 모든 응답은 유효하고 상한 미만이라는 전제다. 특정 모델이 이 비용으로 응답하는지, 혼합 상대가 추가 TALK를 유발하는지, 이 정책이 최적/지배 전략인지는 확인하지 않았다. 현재 v12는 `allow_pass=false`이므로 이 반례를 기존 v12 실행 결과로 적용하지 않는다.

**해석:** 보상 희석 제거는 확인 가능한 설계 변화지만, 풀기·공유가 보상 획득에 필요하다는 뜻은 아니다. 세 축 분리와 종합 순위 금지(07:89)는 유지해야 한다. 종료 보상·잔존만 높은 정책을 유효한 문제 해결·협력 성공으로 읽으면 점수 해석을 쉽게 부풀릴 수 있다. 한편 잔액을 더 보존하려는 행위자는 정답 환급을 선호할 수 있으므로 PASS의 보편적 우월성을 주장하지 않는다.

**최소 수정안:** 최종 문서에 위 반례와 다음 선택을 명시한다. 권고는 현재 수치를 유지하되 이를 **참여/자원관리 기준선**으로만 채택하고, 종료 보상은 능력·협력의 결합 성공 기준이 아니라고 적는 것이다. 항상 DONE/PASS, 항상 EXIT, 전원 공유, 보답 기회가 있는 무임승차를 후속 오프라인 정책 비교 명세에 넣는다. 만약 게임 보상 자체가 세 능력의 결합을 요구해야 한다면, 그 목표의 미충족을 보류로 남기고 game-designer의 별도 규칙 수정 대상으로 지정한다. 원하는 결과에 맞춰 upkeep만 조정하지 않는다.

**수용 기준/담당:** arena-director가 어느 목표를 채택했는지 기록하고 무해결 정책의 허용 결과·해석 경계를 최종 문서에 넣는다. 이 명시로 문서 결함을 해소할 수 있다. 정책 하네스 실행은 이번 통과 요건이 아니며 후속 승인 구현에서 arena-engineer, 검증은 arena-verifier 담당이다.

### W1 · Warning — 공식 예제 후보집합과 자유문으로 얻은 정보의 범위가 불명확

**위치/근거:** 07:31, 53, 136은 자유문·간접 참조·금액 부호화를 인정하지만, 97–103의 ‘미보유’, ‘후보 수 전−후’, ‘허용 관측’에는 그 경로의 계측 경계가 고정되어 있지 않다. 03 §5와 05 §3도 경로 구분을 요구한다. 실제 `e52_game.py:435–438`의 candidates는 예제 목록에서 계산되고 `channel.py:132–134`의 received는 공식 예제 제공자를 저장한다. `protocol.py:232–241`은 어휘필터다.

**해석:** 상대가 TO의 간접 참조로 이미 같은 정보를 전달한 뒤 공식 EXAMPLE을 보내면, 공식 장부만 본 후보 감소를 ‘새로 얻은 총 정보’로 과대계상할 수 있다. 반대로 공식 교환 없이 전달한 도움을 0으로 처리할 수 있다. 이는 실제 인지·복원 성공의 증거가 아닌 계측 범위 문제다.

**최소 수정안:** 정확 재구성이 가능한 값은 ‘공식 배포/EXAMPLE 장부 기준 후보집합 감소’와 ‘공식 미보유 예제’로 이름을 제한한다. TO·OFFER 패턴의 비공식 정보 경로는 별도 표시한다. 의미를 검증할 수 없는 전체 정보 효과는 NA이며 공식 효과 0과 같지 않다. 공식 경로와 비공식 경로를 중복 합산하지 않는다. 비공식 메시지는 부정확할 수도 있으므로 문자열을 참인 단서로 자동 추가하지 않는다.

**수용 기준/담당:** 간접 전달 후 공식 재전달, 공식 거래 없는 간접 전달의 두 경우에 무엇이 0/양수/NA인지 문서로 판별 가능해야 한다. 최종 정의는 arena-director가 기록하고 계측 계약은 metric-analyst, 복원 진단은 beta-tester 담당이다. 자유문 의미 검열을 추가하라는 요구가 아니다.

### W2 · Warning — EXIT와 협력 단계별 비율의 분모가 일부 생략됨

**위치/근거:** 07:94–97은 참여 곡선의 최초 좌석 분모와 도움 방향쌍-라운드를 명시하지만 EXIT 의도율, 제안율, 수락률, 실행률의 정확한 각 분모는 없다. 04의 ‘제안: 세 축별 측정표’에는 EXIT의 전체 TALK 호출 기회와 유효 응답 조건부 비율 병기가 있다. 07:103의 일반 NA 원칙만으로 단계별 비율을 재현할 수는 없다.

**최소 수정안:** 각 비율을 사용한다면 분자/분모/단위를 짧은 표로 보완한다. 예: EXIT 의도는 스케줄된 TALK 응답 기회 및 유효 응답 기회를 각각 분모로 하고, DONE 때문에 애초 호출되지 않은 슬롯은 분리한다. 실제 EXIT 적용은 좌석별 사건이다. 적격 방향쌍-라운드 제안/실행은 같은 방향쌍의 중복 제안을 중복 계수하지 않는다. 제안 ID 기준 수락률은 실제 수락 기회가 있었던 유효 제안 ID를 분모로 하고 마지막 턴 신규 제안·무효 ID는 별도 집계한다. 다른 정의를 채택해도 좋으나 사건 수, 호출 수, 방향쌍 수를 섞지 않는다. 계산하지 않을 비율은 원시 건수만 보고한다고 명시하면 된다.

**수용 기준/담당:** 분모 0과 로그 미확인 NA를 구별하고, provider 실패·잘림·미적용 EXIT·중복 제안의 포함 여부가 결정되어야 한다. arena-director가 최종 문서에 반영하고 metric-analyst가 후속 계산 계약을 소유한다. 현재 수치를 산출하거나 과거 로그를 재분석하라는 요구는 아니다.

## 3. 실제 검증 기록과 재현

아래 명령은 모두 지정 복제본을 작업 디렉토리로 실행했다.

- `git branch --show-current`, `git rev-parse HEAD`: 위 브랜치·HEAD 확인.
- `git -c filter.lfs.process= -c filter.lfs.required=false -c filter.lfs.clean=cat status --short --untracked-files=no`: 성공, 추적 파일 변경 출력 없음. 명령 한정 옵션이며 Git/LFS 설정을 변경하지 않았다.
- `nl -ba`, `cat`, `sed`: 00~07 및 위 소스 위치 실제 열람. 파서 위험은 코드 독해만 수행했으며 파서 함수 실행 PASS라고 하지 않는다.
- Python 표준 라이브러리 `hashlib.sha256`: `snapshot.json.baseline_hashes` 69개를 실제 재계산, 불일치/누락 0. 보호 해시 범위는 snapshot에 열거된 파일에 한정되며 원본 전체·LFS 대용량 객체·paper 내부의 전수 검증을 뜻하지 않는다.
- Python 산식/조건 assertion: 정답 예시 19,800, 오답 15,000, PASS 18,760; 축약 파일럿 240슬롯, v12 형식상 480슬롯; C1의 최종 5,120. 모두 일치.

C1에서 도구가 출력한 라운드별 잔액:

`[18760, 17520, 16280, 15040, 13800, 12560, 11320, 10080, 8840, 7600, 6360, 5120]`

재현용 최소 명령(엔진 import·모델 호출·파일 쓰기 없음):

```bash
python3 - <<'PY'
import hashlib, json
from pathlib import Path
root = Path('docs/agents/review-2026-10-07')
baseline = json.loads((root / 'snapshot.json').read_text())['baseline_hashes']
bad = [p for p, h in baseline.items()
       if not Path(p).is_file() or hashlib.sha256(Path(p).read_bytes()).hexdigest() != h]
assert not bad, bad
balance, trajectory = 20000, []
for _ in range(12):
    balance -= 200  # Hypothetical total TALK cost, not measured model usage.
    assert 40 < min(16384, balance)
    balance -= 40 + 1000  # Hypothetical valid PASS plus upkeep.
    trajectory.append(balance)
assert min(trajectory) > 0 and balance == 5120
assert (20000-200-800+800, 20000-200-800-3000-1000, 20000-200-40-1000) == (19800,15000,18760)
assert (1*4*4*3*(4+1), 1*2*4*12*(4+1)) == (240,480)
print({'baseline_count': len(baseline), 'mismatches': bad, 'balances': trajectory})
PY
```

위 재현 코드는 문서의 산식과 보호 해시만 확인한다.

구현·회귀시험·모델 응답·인간 재미·구성개념 타당성·가격/현금 비용은 계속 미검증이다. 기존 자식 카드가 최종 문서를 담당하므로 이 카드를 완료해 의존성을 해제한다. kanban_attach는 이 세션에 공개되어 있지 않아 산출물은 kanban_complete의 artifacts로 인계한다.
