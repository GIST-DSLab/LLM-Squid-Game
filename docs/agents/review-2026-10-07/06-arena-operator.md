arena-operator — 실험 비용·모델 온보딩

상태: 제안·운영 검토. 제공된 발췌만 근거로 했으며, 파일 열람·수정·실험 실행은 하지 않았다.

## 관찰과 해석

관찰: 설정에는 모델별 CLI 경로와 `think`, timeout, 게임 호출 상한이 있지만 금액 예산이나 청구 기록은 없다. 엔진은 생성 토큰을 게임 잔액에서 차감한다.  
해석: 현재 설정만으로 감당 가능한 실제 비용이나 모델 간 비용 비교를 입증할 수 없다. 아래 5개 항목을 파일럿 설계의 최소 변경안으로 제안한다.

## 핵심 이슈 및 최소 변경

1. **Critical — 온보딩 시 모델·실행 경로를 고정할 것**  
   근거: `configs/squid5/e52v12_coop_smoke_mix4.yaml:39-45`  
   관찰: 좌석마다 `claude_cli` 또는 `codex_cli`, 모델명, `think: high`, timeout이 지정돼 있다.  
   최소 변경: 온보딩 카드에 실제 해석된 모델 버전, CLI·relay 버전과 경로, 추론 설정, 엔진 commit, config 식별자, 토큰 사용량의 의미를 기록한다.  
   수용 기준: 모델 별칭만으로 실행을 식별하지 않고, 모든 항목이 기록되거나 미확인으로 표시된다.

2. **Critical — 호출 상한·재시도·지연 기록을 사전 고정할 것**  
   근거: `squid5/e52_game.py:289-329,331-368`; `configs/squid5/e52v12_coop_smoke_mix4.yaml:9-20`  
   관찰: 호출은 에이전트별 한 번씩 동시 수행되며 TALK와 SOLVE에 별도 상한이 있다. 설정의 `workers`는 세션 병렬도이지 전체 호출 상한이 아니다.  
   제안: 셀 수를 \(C\), 반복 수 \(N\), 좌석 수 \(A\), 라운드 수 \(R\), TALK 턴 상한 \(K\), 호출당 재시도 횟수 \(q\)라 하면,
   \[
   \text{호출 슬롯 상한}=C N A R(K+1),\quad
   \text{제공자 시도 상한}=C N A R(K+1)(1+q).
   \]
   파일럿에서는 자동 재시도를 끄고 실패를 실패로 기록한다. 지연은 각 TALK 턴의 병렬 호출 중 최장 지연과 SOLVE 최장 지연을 라운드별로 기록해 합산한다.  
   수용 기준: 내부 재시도 여부·timeout 적용 범위·시도 ID를 확인하고, 단계별 지연·실패·재시도 횟수를 남긴다. 파싱 오류나 잘림은 조용히 재호출하지 않는다.

3. **Critical — 게임 토큰과 실제 청구액을 분리할 것**  
   근거: `CLAUDE.md:34,44`; `squid5/e52_game.py:277-328,473-480`  
   관찰: 프로젝트의 `out_tokens`는 생각 토큰을 포함하며 게임 잔액 차감은 `min(out_tokens, cap, balance)`에 기반한다.  
   최소 변경: 게임 자원 토큰과 제공자 사용량·청구액을 별도 필드로 기록한다. 실제 비용은 제공자 사용량 및 청구 근거로 계산하고, relay 비용과 구독형 고정 비용은 별도 항목으로 둔다. 예컨대 사용량 기반 비용은
   \[
   C_{\text{cash}}=\sum_j(I_jp_{\text{in}}+O_jp_{\text{out}}+H_jp_{\text{cached}}+F_j)
   \]
   로 계산하고, 고정 비용 배분을 포함한다면 현금 청구액과 분리해 보고한다.  
   수용 기준: 제공자 사용량·청구 기록과 요청을 대조한다. 자료가 없으면 실제 비용은 미측정으로 표시하고 `out_tokens`로 대체 추정하지 않는다.

4. **Warning — 비교 예산과 공통 비교 단위를 결과 전에 고정할 것**  
   근거: `configs/squid5/e52v12_coop_smoke_mix4.yaml:9-20,32-50`; `squid5/e52_game.py:253-256`  
   관찰: 네 모델이 서로 다른 좌석과 provider 경로에 배치된 혼합 게임이다. 좌석별 상호작용 결과를 단일 모델 능력 차이로 해석할 수 없다.  
   제안: 모든 후보에 같은 세션·시드·좌석 균형화 규칙과 동일한 게임 상한을 적용한다. 모델별 금액 상한 \(B_i\)를 같게 사전 지정하고, 전체 상한은 \(\sum_i B_i+\text{공유 비용}\le B_{\text{승인}}\)으로 둔다. 비용 상한에 걸리면 해당 비교 블록을 불완전으로 처리하고, 결과를 본 뒤 특정 모델만 추가 표집하지 않는다.  
   수용 기준: 후보별 동일한 사전 지정 비교 블록이 완료됐거나, 미완료·중단 사유가 명시된다. 혼합 팀 결과는 cross-play로 표시한다.

5. **Suggestion — 유지 가능한 소규모 파일럿으로 온보딩만 먼저 판정할 것**  
   근거: `configs/squid5/e52v12_coop_smoke_mix4.yaml:9-20,39-50`; `CLAUDE.md:61-63`  
   제안: 승인된 상한 안에서 고정된 최소 공통 비교 블록을 사전 지정한다. 온보딩 카드와 함께 세션별 비용, 지연, 유효 응답률, 실패 유형, 설정 시간을 기록한다. API/provider 실패는 행동 결과나 0점으로 치환하지 않고, 재실행은 별도 시도와 예산으로 기록한다. 이번 파일럿의 판정은 연결·설정·비용·지연의 실행 가능성에 한정하며 모델 순위나 심리적 결론을 내리지 않는다.  
   수용 기준: 다른 담당자가 카드·고정 설정·비용 근거만으로 같은 블록과 중단 규칙을 재현할 수 있다.

## 미검증 및 인계

모델 별칭의 실제 버전, CLI 내부 재시도, 제공자 사용량·청구 자료, 입력 토큰 상한, relay 요금·지연, 실행 로그는 제공 근거에서 확인되지 않았다. 실제 금액 상한은 가격 근거와 승인 예산이 정해져야 채울 수 있다. **이번 검토에서는 유료 실행을 시작하지 않는다.**

고정 상금·숨은 지평·EXIT 의미는 `game-designer`와 `construct-auditor`, action-filter 우회는 `beta-tester`, 현재 코드와 측정 지표의 버전 정합성은 `metric-analyst`와 `arena-verifier` 검토 대상이다.

## 채택·보류 권고

- **채택 권고:** 온보딩 카드, 호출·재시도 상한식, 게임 토큰과 현금 청구의 분리, 결과 전 고정한 모델별·전체 예산 상한, 고정 최소 비교 블록.
- **보류:** 실제 파일럿 실행, 비용·순위 결론. 모델 버전·청구 근거·입력 상한을 확인하고 실행 예산을 승인받기 전까지 진행하지 않는다.
