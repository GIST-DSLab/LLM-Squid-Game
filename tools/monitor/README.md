# 아레나 모니터 (5.2 v9-talk)

한 세션(게임)에서 에이전트 넷이 1:1로 말하고, 제안을 내고 받고, 퍼즐을 풀고, 토큰을 쓰는 과정을 실시간으로 보고 디버깅하는 도구다. 엔진이 쓰는 `events.jsonl`을 읽기만 하고 엔진 코드는 건드리지 않는다. 서버는 파이썬 표준 라이브러리만 쓰고, 페이지는 바닐라 JS와 인라인 SVG로 그린다(구글 폰트만 외부에서 불러옴). 게임 엔진의 5,000줄 제한(`squid5/`, `tests/`)에는 들어가지 않는다.

## 실행

```bash
# 1) 서버: 기본 루트 ~/squid5-runs, 포트 8765(쓰고 있으면 8766, 8767 … 순서로 빈 포트를 찾음)
python3 tools/monitor/serve.py [--root ~/squid5-runs] [--port 8765] [--host 127.0.0.1]
#    → 출력된 주소를 브라우저로 연다. 예: http://127.0.0.1:8765/
#    바로가기: http://127.0.0.1:8765/?run=<루트 기준 실행 경로>&session=<session_id>[&at=<이벤트 번호>][&theme=dark][&sprites=0]

# 2) 내보내기: 한 세션을 서버 없이 열리는 HTML 파일 하나로
python3 tools/monitor/export.py <RUN_DIR> [--session <session_id>] --out session.html [--no-assets]

# 3) 스프라이트(선택): Survival-Games 로컬 클론에서 캐릭터 넷과 말풍선을 tools/monitor/assets/로 복사
git clone https://github.com/hong123123/Survival-Games /tmp/sg
python3 tools/monitor/fetch_assets.py --from /tmp/sg

# 테스트(저장소 루트에서)
python3 -m pytest -q tools/monitor
```

`--session`을 빼면 그 실행의 첫 세션을 내보낸다.

### `/api/puzzle?run=<실행>&session=<session_id>&round=<N>`

그 라운드의 과제를 엔진으로 다시 만들어 JSON으로 준다. 서버는 이 경로에서만 저장소 루트의 `squid5`(퍼즐 코드)와 PyYAML(`config.yaml` 읽기)을 불러온다. 필드: `round`, `profile`, `shape_hint`, `public`(`[{signal:{color,shape,number,text}, text, action}]`), `queries`(`[{color,shape,number,text}]`), `answers`, `rule_text`(예: `if number >= 3 → go_right; elif color == "red" → jump; …; else → go_left`), `agents`(`{agent: {secret, needed, public_only:[[행동…] 신호마다], with_own:[[행동…] 신호마다]}}`), `timing_ms`(첫 계산 시간). 라운드가 정수가 아니거나 1..라운드 수 밖이면 400, 세션이 없으면 404, 루트 밖 실행은 400, 엔진 쪽 실패는 500 — 모두 `{"error": …}`. 실행 하나에는 여러 세션이 섞여 기록되므로 서버와 내보내기 모두 `session_id`로 걸러 낸다.

## 화면

- **머리줄**: 실행·세션 선택(● 진행 중, ✓ 끝남), 라운드 x/전체, 지금 단계(UPKEEP / TALK k턴 / EXCHANGES / SOLVE / SETTLEMENT / 종료), 실시간 표시(● 실시간 · ○ 대기 · ■ 완료 · ✕ 오류), 테마 전환. 그 아래 재생 막대: 아무 이벤트까지 되감으면 모든 패널이 이벤트 0..i로 다시 계산된다. ◀ ▶ 또는 ←/→는 한 이벤트씩, ⏪ ⏩는 라운드 경계로, ⏭ 또는 End는 최신으로 돌아가 실시간 따라가기를 켠다. 1.5초마다 새 줄만 받아 온다(바이트 오프셋, 반쯤 쓰인 마지막 줄은 다음에).
- **무대**: 네 캐릭터가 픽셀 바닥 위에 나란히 서고, 머리 위 말풍선에 그 시점의 마지막 행동이 짧게 뜬다(`💬 → agent-11: …`, `🤝 제안 2.1 → agent-17: 상대 300 / 나 예시`, `✅ 수락 2.1`, `🚪 EXIT`, `💤 DONE`, `🧠 생각 중…`, `🧩 SOLVE ✓ / ✗ / PASS`, 정산 때 환급·상금·벌금). 호출이 나가 있는 동안 캐릭터가 걷는 동작을 한다. 아래에는 이름·모델, HP처럼 생긴 잔액 막대(잔액 ÷ 시작 잔액, 줄면 초록→노랑→빨강, 눈금 = 시작 잔액), 잔액과 마지막 변화량, 상태(참여 중 / 종료됨 ✕ / 퇴장 🚪), 기록(푼 라운드 수), 이번 라운드 생성 토큰. 0이 된 에이전트는 회색에 ✕, EXIT한 에이전트는 오른쪽으로 걸어 나간다.
- **이번 라운드 문제**: 무대 바로 아래. 재생 막대가 가리키는 라운드(실시간 따라가기면 지금 라운드)의 과제를 보여 준다. 로그에는 과제가 없어서, 엔진이 결정적이라는 점을 써서 `(seed, 라운드, 프로필)`로 다시 만든다(`puzzle_for` → `deal`, 시드는 `session_start`, 프로필은 `round_start`나 `config.yaml`의 `game.schedule`).
  - 위: 과제 이름, 규칙 모양(`if ____: ____; elif …; else: ____`), 공개 예시(넷 다 봄), 새 신호(답할 것). 신호는 색 × 모양 안에 숫자를 넣은 작은 그림 + 글 + 행동 칩(← go_left · → go_right · • stay · ↑ jump)으로 그린다. 신호 색은 에이전트 색과 별개의 토큰이다.
  - 아래: 에이전트 넷의 열(무대와 같은 순서·색). 각 열에 **자기 비밀 예시**, 엔진의 `needed`면 `★ 필수 단서` 배지, 신호마다 두 줄 — `공개만`과 `공개 + 내 단서` — 에 아직 가능한 행동을 칩으로. 넷 다 남으면 아이콘만 있는 점선 칩 + `모름`, 하나면 `결정됨 ✓/✗`(정답과 비교), 자기 예시가 후보를 줄이면 그 줄을 노랗게 칠하고 `내 단서로 4→2`처럼 적는다. 맨 위 요약 줄은 그 라운드에서 공개+자기 예시만으로 결정되는 (에이전트, 신호) 수와 자기 예시가 후보를 줄인 수.
  - **교환으로 받은 예시는 넣지 않는다**(그건 단계별 기록의 SOLVE 카드). 이 패널은 각자가 교환 전에 혼자 알 수 있는 것까지만이다.
  - 접힌 `정답 · 실제 규칙 보기`는 디버그용(정답과 실제 규칙 문장). 기본은 접혀 있어 패널이 에이전트 눈에 보이는 것처럼 읽힌다.
  - 계산: `candidate_actions` 한 번은 실측 30ms 이하지만, 라운드를 만드는 `puzzle_for` + `deal`이 c4tq2에서 0.1–0.7초, c3at에서 최대 1.3초 걸린다(mix4 실행 10세션 × 8라운드). 서버는 `(seed, 라운드, 프로필)`마다 한 번만 계산해 캐시하고, 페이지도 받은 라운드는 다시 묻지 않는다.
- **타임라인**: 논문 그림처럼 가로 선 위 점마다 네 에이전트의 상태 사전 `{'balance': …, 'record': …, 'status': …}`. 지난 라운드는 정산 시점 한 점씩, 지금 라운드는 시작과 TALK 턴마다 한 점. 점을 누르면 그 시점으로 간다.
- **잔액 추이**: 에이전트별 선(색 + 끝 모양 ● ■ ▲ ◆ + 끝 라벨). 호출·교환·정산마다 한 점, 세로선은 라운드 시작, 점선은 시작 잔액, 빨간 점선은 0. 마우스를 올리면 그 시점의 네 잔액, 누르면 그 시점으로 이동.
- **대화**: 1:1 스레드. 전체 또는 짝(6↔11 …)을 골라 메시지와 그 둘 사이의 제안을 라운드·턴 순서로 읽는다.
- **단계별 기록**: 에이전트마다 한 열, 행은 (라운드, TALK 턴) → 교환 → SOLVE → 정산.
  - TALK 카드: 쓴 토큰 / 상한, 잘림·잔액 초과·형식 오류 표시, 호출 뒤 잔액, 보낸 메시지(받는 쪽 색 칩), 제안(번호와 양쪽이 주는 것, 최종 상태), ACCEPT/WITHDRAW 결과(거절이면 엔진의 이유), 무시된 줄, 메시지 줄 끝에 붙어 명령으로 읽히지 않은 DONE/EXIT, EXIT/DONE. 접힌 칸 `생각`(추론 요약), `받은 프롬프트`, `원문`은 펼칠 때 채운다.
  - 제안 번호는 호출 기록에 없어서 페이지가 엔진(`Session._apply`, `Channel.accept/withdraw`)과 같은 순서로 다시 매기고, TALK 끝의 `exchange` 기록과 어긋나면 경고를 띄운다.
  - 교환 행: 이번 라운드 제안 전부(체결 / 무효 / 만료 / 철회, 무효 이유).
  - SOLVE 카드: 답과 정답(✓ / ✗ / PASS / 무효), 교환으로 받은 예시, 신호별 남은 후보 수, 이 에이전트의 예시가 필요한지와 빠진 필요 예시, 토큰.
  - 정산 행: 시작→끝 잔액, 생성·환급·상금·벌금·유지비, 보낸 메시지·제안·수락 수, 엔진이 거절한 줄(`refused`), 관련 교환.
- 세션이 끝나면 최종 상금 받은 에이전트를, 크래시(`unit_error`)면 오류 문구를 맨 위에 띄운다. 라이트/다크는 OS 설정을 따르고 버튼으로 바꿀 수 있다. 좁은 화면에서는 무대와 네 열이 가로로 스크롤된다.

## 스프라이트 라이선스

Survival-Games 저장소(Chen et al. 2025)의 **코드**는 Apache-2.0이지만 픽셀 캐릭터와 말풍선 그림은 **다른 작가의 제3자 아트**다(Generative Agents가 캐릭터는 pipohi, 맵·실내는 PixyMoon과 LimeZu로 밝힘). 그래서 PNG를 저장소에 넣지 않는다. `fetch_assets.py`가 각자의 로컬 클론에서 `tools/monitor/assets/`로 복사하고(이 폴더는 `.gitignore`), 출처와 주의를 적은 `NOTICE.txt`를 함께 쓴다. 에셋이 없으면 페이지는 에이전트 색으로 칠한 12×12 픽셀 아바타와 CSS 말풍선으로 그린다(`?sprites=0`으로 일부러 볼 수도 있다). 스프라이트를 넣어 내보낸 HTML은 그 그림을 품으므로 연구실 밖으로 돌리지 말고, 공유할 때는 `--no-assets`로 내보낸다.

## 파일

| 파일 | 역할 |
|---|---|
| `serve.py` | HTTP 서버(`/`, `/static/*`, `/assets/*`, `/api/runs`, `/api/sessions`, `/api/events`, `/api/puzzle`)와 실행 읽기 함수. 루트 밖 경로는 400 |
| `monitor.html`, `static/monitor.{js,css}` | 페이지. 상태는 늘 이벤트 0..i에서 다시 계산 |
| `export.py` | 세션 하나를 자체 완결 HTML로(이벤트와, 시작된 라운드마다 다시 만든 과제(`puzzles`)를 `<script type="application/json" id="monitor-data">`에 넣음 — 서버 없이도 문제 패널이 뜬다) |
| `fetch_assets.py` | 스프라이트 복사 + `manifest.json` + `NOTICE.txt` |
| `test_monitor.py` | 합성 실행(Stub 공급자로 `Session`을 돌림)으로 API·증분 읽기·경로 거부·과제 재구성(엔진을 직접 돌린 값과 같은지, `공개 + 내 단서` ⊆ `공개만`, 정답이 늘 후보 안에, 잘못된 라운드·세션은 4xx)·내보내기(과제 포함)·JS 문법·페이지의 제안 장부 재현을 확인 |
