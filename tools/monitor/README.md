# 아레나 모니터 (5.2 v9-talk – v22)

한 세션(게임)에서 에이전트 넷이 1:1로 말하고, 제안을 내고 받고, 퍼즐을 풀고, 토큰을 쓰는 과정을 실시간으로 보고 디버깅하는 도구다. 엔진이 쓰는 `events.jsonl`을 읽기만 하고 엔진 코드는 건드리지 않는다. 서버는 파이썬 표준 라이브러리만 쓰고, 페이지는 바닐라 JS와 인라인 SVG로 그린다(구글 폰트만 외부에서 불러옴). 게임 엔진의 5,000줄 제한(`squid5/`, `tests/`)에는 들어가지 않는다.

## 실행

```bash
# 1) 서버: 기본 루트 ~/squid5-runs, 포트 8765(쓰고 있으면 8766, 8767 … 순서로 빈 포트를 찾음)
python3 tools/monitor/serve.py [--root ~/squid5-runs] [--port 8765] [--host 127.0.0.1]
#    → 출력된 주소를 브라우저로 연다. 예: http://127.0.0.1:8765/
#    바로가기: http://127.0.0.1:8765/?run=<루트 기준 실행 경로>&session=<session_id>[&at=<이벤트 번호>][&theme=dark][&sprites=sheets]

# 2) 내보내기: 한 세션을 서버 없이 열리는 HTML 파일 하나로
python3 tools/monitor/export.py <RUN_DIR> [--session <session_id>] --out session.html [--sheets]

# 3) (선택, 로컬 전용) 옛 제3자 스프라이트: Survival-Games 클론에서 tools/monitor/assets/로 복사한 뒤 ?sprites=sheets / --sheets로만 씀
git clone https://github.com/hong123123/Survival-Games /tmp/sg
python3 tools/monitor/fetch_assets.py --from /tmp/sg

python3 tools/monitor/v22_fixture.py /tmp/v22_fixture_run
```

`--session`을 빼면 그 실행의 첫 세션을 내보낸다.

웹 아레나 서버(`uvicorn web.server.app:app --port 8600`) 안에서도 열린다: `http://localhost:8600/monitor/`(API는 `/monitor/api/...`, 루트는 `WEB5_MONITOR_ROOT` 또는 `WEB5_RUNS_ROOT`의 부모 = `~/squid5-runs`). `web/server/monitor.py`가 이 폴더의 `serve.py` 함수를 그대로 불러 쓰고, 페이지는 `api/`·`static/`·`assets/`를 상대 경로로 부르므로 두 곳에서 같은 파일이 돈다. 그 경로에서만 헤더에 홈·아레나 링크가 보인다.

### `/api/puzzle?run=<실행>&session=<session_id>&round=<N>`

그 라운드의 과제를 엔진으로 다시 만들어 JSON으로 준다. 서버는 이 경로에서만 저장소 루트의 `squid5`(퍼즐 코드)와 PyYAML(`config.yaml` 읽기)을 불러온다. 필드: `round`, `profile`, `shape_hint`, `public`(`[{signal:{color,shape,number,text}, text, action}]`), `queries`(`[{color,shape,number,text}]`), `answers`, `rule_text`(예: `if number >= 3 → go_right; elif color == "red" → jump; …; else → go_left`), `agents`(`{agent: {secret, needed, public_only:[[행동…] 신호마다], with_own:[[행동…] 신호마다]}}`), `timing_ms`(첫 계산 시간).
**v14 실행**(`round_start`에 `public`이 있거나 `game.public_per_agent`)은 `mode: "public"`이고 `agents`(비밀 열)가 없다: `public`은 그
라운드 `round_start.public.examples`(에이전트가 본 그대로), `per_agent`·`n`(라운드 시작 때 참여 인원)·`ambiguity`(k)·`attempt`(규칙
재추첨 수), `left`(신호마다 그 예시로 남는 행동), `by_n`(`[{n, count, left}]`, 참여 1..4명일 때 = 같은 순서의 앞부분),
`matches_log`(`puzzle.public_round`로 다시 만든 예시·규칙이 기록과 같은지; 다르면 기록을 보여 주고 `by_n`은 비움), `taking_part`. 라운드가 정수가 아니거나 1..라운드 수 밖이면 400, 세션이 없으면 404, 루트 밖 실행은 400, 엔진 쪽 실패는 500 — 모두 `{"error": …}`. 실행 하나에는 여러 세션이 섞여 기록되므로 서버와 내보내기 모두 `session_id`로 걸러 낸다.

## 화면

- **머리줄**: 실행·세션 선택(● 진행 중, ✓ 끝남), 라운드 x/전체, 지금 단계(R 시작 / TALK k턴 / EXCHANGES / SOLVE / SETTLEMENT / 종료), 실시간 표시(● 실시간 · ○ 대기 · ■ 완료 · ✕ 오류), 테마 전환. 그 아래 재생 막대: 아무 이벤트까지 되감으면 모든 패널이 이벤트 0..i로 다시 계산된다. ◀ ▶ 또는 ←/→는 한 이벤트씩, ⏪ ⏩는 라운드 경계로, ⏭ 또는 End는 최신으로 돌아가 실시간 따라가기를 켠다. 1.5초마다 새 줄만 받아 온다(바이트 오프셋, 반쯤 쓰인 마지막 줄은 다음에).
- **v14 실행**: `session_start.starts`로 자리마다 시작 잔액(설정의 몫 100/75/50/25%)에서 출발한다. 무대의 잔액 막대 = 잔액 ÷ 세션 시작
  잔액(`start`, v14는 20,000 = 엔진이 보여 주는 %의 100%), 눈금 = 그 자리의 시작 잔액, 숫자 옆에 %. `exit_refill` 기록이 오면 잔액이
  그 자리의 시작 잔액으로 돌아가고 `EXIT → 시작 잔액으로` 배지(무대·정산 행·단계별 기록의 "EXIT 리필" 행·끝 말풍선)가 붙는다.
  제안은 토큰만이므로 제안 그래프의 종류는 선물(주기만) · 요청(받기만) · 토큰 ⇄ 토큰, SOLVE 카드에는 교환 예시·필요 예시 줄이 없다.
  문제 패널은 에이전트별 열 대신 공개 예시(한 명 몫마다 점선), k와 재추첨, 이번 참여 인원에서 남는 답, 참여 1..4명별 남는 답을 보인다.
  세션이 끝나면 끝 지급(남은 수 × `survivor_bonus`)을 띄운다.
- **무대**(10-17부터 위 영역의 왼쪽 절반): 한 줄에 한 자리. 왼쪽 픽셀 바닥 칸에 캐릭터, 바로 옆에 이름과 캐릭터 번호(#456 …), 상태(참여 중 / 종료됨 ✕ / 퇴장 🚪), 모델, HP처럼 생긴 잔액 막대(잔액 ÷ 시작 잔액, 줄면 초록→노랑→빨강, 눈금 = 시작 잔액), 잔액과 마지막 변화량, 기록(푼 라운드 수)·이번 라운드 생성 토큰, 오른쪽 말풍선에 그 시점의 마지막 행동(`💬 → agent-11: …`, `💸 GIVE …`, `💤 DONE`, `🧠 생각 중…`, `🧩 SOLVE ✓ / ✗`, 정산 때 환급·벌금). 호출이 나가 있는 동안 캐릭터가 걷는 동작을 한다. **이번 라운드 solver**(v15 대표 포함)는 줄 전체에 굵은 빨간 테두리와 `SOLVER` 배지(빨간 ✕가 찍힌 검은 추첨표 픽셀 아이콘 — 나쁜 제비)를 단다; 같은 아이콘이 말풍선·단계별 기록·토큰 흐름 머리(✖)에도 쓰인다. v22가 아닌 실행은 오른쪽 절반이 없어 두 줄씩 넓게 놓인다.
- **SOLVE 답**(무대 바로 아래): 재생 막대 라운드의 SOLVE 호출마다(v16+ = solver 하나, 옛 실행 = 푼 자리 모두) 답(ACTIONS) 칩과 정답(`answers`, 없으면 `round_start.public.answers`, 둘 다 없으면 엔진의 `results.solved`), ✓ 정답 / ✗ 오답, BELIEF 줄(출력에서 읽어 막대로), 생성 토큰 ÷ 한도(막대, %, 잘림·잔액 초과 표시), 결과(환급 또는 벌금 예고), 그리고 눌러서 여는 `생각 요약` · `출력 그대로` · `USER 프롬프트`. SOLVE 전이면 `아직 SOLVE 전`.
- **라운드 흐름 + 진행요원**(v22 실행에서만, 위 영역의 오른쪽 절반): 보고서 `e53_build/v22_round`의 상자 0–12(세션 시작 · solver 추첨 · SOLVE 전 틱 루프 2–4 · EXIT 효력 · SOLVE · 결과 · 결과 뒤 틱 루프 8–10 · 벌금 · 다음 라운드)를 작게 다시 그린다. 재생 막대가 있는 단계(`rfStepOf`: 이벤트 종류와 `phase`로 정함)에 굵은 테두리와 `지금`. 아래 분홍 옷 진행요원(가면의 ○ = SOLVE 전, □ = 결과 뒤, △ = 나머지; 우리 픽셀 아트)이 말풍선으로 고른 상자의 **USER 프롬프트**를 읽어 준다: 3·9 = 그 라운드 그 TALK의 자리별 마지막 호출(기본 = 가장 최근, 자리 버튼으로 바꿈), 6 = SOLVE 호출, 엔진 상자 = 한 줄 설명 + 그 라운드의 사실(부른 자리, 틱 끝 집계, 결과, 벌금 …). 상자를 누르면 그 상자, 다시 누르면 지금 단계로. `▶ 이 호출로`는 재생 막대를 그 호출로 옮긴다. 좁은 화면(1100px 이하)에서는 두 절반이 위아래로.
- **이번 라운드 문제**: 메신저 · 제안 그래프 줄 아래. 재생 막대가 가리키는 라운드(실시간 따라가기면 지금 라운드)의 과제를 보여 준다. 로그에는 과제가 없어서, 엔진이 결정적이라는 점을 써서 `(seed, 라운드, 프로필)`로 다시 만든다(`puzzle_for` → `deal`, 시드는 `session_start`, 프로필은 `round_start`나 `config.yaml`의 `game.schedule`).
  - 위: 과제 이름, 규칙 모양(`if ____: ____; elif …; else: ____`), 공개 예시(넷 다 봄), 새 신호(답할 것). 신호는 색 × 모양 안에 숫자를 넣은 작은 그림 + 글 + 행동 칩(← go_left · → go_right · • stay · ↑ jump)으로 그린다. 신호 색은 에이전트 색과 별개의 토큰이다.
  - 아래: 에이전트 넷의 열(무대와 같은 순서·색). 각 열에 **자기 비밀 예시**, 엔진의 `needed`면 `★ 필수 단서` 배지, 신호마다 두 줄 — `공개만`과 `공개 + 내 단서` — 에 아직 가능한 행동을 칩으로. 넷 다 남으면 아이콘만 있는 점선 칩 + `모름`, 하나면 `결정됨 ✓/✗`(정답과 비교), 자기 예시가 후보를 줄이면 그 줄을 노랗게 칠하고 `내 단서로 4→2`처럼 적는다. 맨 위 요약 줄은 그 라운드에서 공개+자기 예시만으로 결정되는 (에이전트, 신호) 수와 자기 예시가 후보를 줄인 수.
  - **교환으로 받은 예시는 넣지 않는다**(그건 단계별 기록의 SOLVE 카드). 이 패널은 각자가 교환 전에 혼자 알 수 있는 것까지만이다.
  - 접힌 `정답 · 실제 규칙 보기`는 디버그용(정답과 실제 규칙 문장). 기본은 접혀 있어 패널이 에이전트 눈에 보이는 것처럼 읽힌다.
  - 계산: `candidate_actions` 한 번은 실측 30ms 이하지만, 라운드를 만드는 `puzzle_for` + `deal`이 c4tq2에서 0.1–0.7초, c3at에서 최대 1.3초 걸린다(mix4 실행 10세션 × 8라운드). 서버는 `(seed, 라운드, 프로필)`마다 한 번만 계산해 캐시하고, 페이지도 받은 라운드는 다시 묻지 않는다.
- **게임 전체 · 토큰 흐름**(10-17부터 모델 분석 패널 위): 재생 막대와 상관없이, 받아 온 이벤트 전부로 게임 처음부터 끝까지를 정지 그림 한 장으로 그린다(`gameFlow(events)` → `renderFlow`). 위: **잔액 차트 하나에 라운드 안 단계까지**. 라운드 칸(경계 0..R, 세로선)을 단계 칸으로 나누고(옅은 음영 + 두 줄 라벨) 자리마다 계단 선이 단계를 따라 움직인다. 단계 = 순번 게임 `TALK·전`(SOLVE 전 TALK) → `SOLVE`(solver의 생각, 풀면 환급) → `TALK·후`(결과 뒤 TALK) → `벌금`(charges) → `EXIT`(그 라운드에 EXIT가 있을 때만), VOTE 게임 `공개·투표` → `SOLVE` → `TALK` → `벌금`, 옛 실행 `TALK` → `SOLVE` → `정산`(round 행의 환급·벌금). 단계마다의 변화는 이벤트에서 계산한다: 호출 `used`(종류별, SOLVE 전/후는 그 라운드의 SOLVE `call_start`·`results` 앞뒤로), `gift`(엔진이 단 `phase`, 없으면 SOLVE 앞뒤), `results.returned`, `charges.taken`·`waived`·`dead`, `exit_refill`. 계단은 그 단계 칸 안에서 자리마다 조금씩 다른 x에서 꺾이고, 라운드 마지막 단계는 늘 `round.end`에 닿는다(장부로 설명 안 되는 차이는 마지막 단계의 `기타`; v16 실행에서는 0). 표시: solver ✓✗는 SOLVE 단계의 꺾임 옆, ✕(0이 되어 꺼짐)는 그 단계, 🚪 EXIT는 EXIT 칸, 라운드 머리에 👑(순번 실행은 solver 표시 ✖)와 ✓/✗, 떠난 뒤 남긴 잔액은 점선. 진행 중인 라운드는 끝난 라운드 뒤에 `R⏳ 진행 중` 칸으로, 지금까지 닿은 단계까지만 옅은 점선으로 그린다(합계·라운드 내역에는 넣지 않음). 계단의 가로 구간(자리 × 단계)과 단계 라벨에 마우스를 올리거나 누르면 시작 → 끝과 이유(생성 종류별, 누구에게 얼마, 환급, 벌금, 면제, 기타)가, 라벨은 네 자리를 한꺼번에 띄우고, **더블클릭하면 재생 막대가 그 단계의 마지막 이벤트로** 간다. 가운데(그대로): 자리 줄 사이 세로 화살표 하나가 GIVE 하나(점 = 주는 쪽, 화살촉 = 받는 쪽, 굵기 ∝ 양, 실선 = 대화 GIVE, 점선 = 결정 GIVE, v9–v13은 체결 제안의 토큰) — 이제 그 GIVE가 일어난 단계 칸 안에 놓이고 SOLVE 전 TALK의 GIVE는 빈 점. 아래(그대로): 라운드 내역 — 자리 × 라운드 칸마다 나간 토큰(생성 · 보냄 · 벌금, 점선 칸 = EXIT로 면제된 벌금)을 왼쪽, 들어온 토큰(환급 · 받음 · 리필)을 오른쪽으로 쌓은 막대와 순변화. **따로 있던 `잔액 추이` 패널(호출마다 한 점, `renderChart`)은 이 그림과 겹쳐 지웠다** — 라운드 안의 움직임은 이제 위 계단이, 그 시점으로 가기는 더블클릭이 맡는다.
- **v16e 순번(rotation) 실행**: `vote` 이벤트에 `drawn`이 있으면 투표 대신 "SOLVER X (시스템이 정함)"(검은 추첨표 아이콘)으로 읽는다. 한 라운드에 TALK가 둘(SOLVE 전 = prep, 결과 뒤 = rescue)이라 단계 기록은 SOLVE 전 TALK 행을 SOLVE 위에, 결과 뒤 TALK 행을 아래에 두고 행 머리·대화 카드·대화 줄·이벤트 설명에 `SOLVE 전` / `결과 뒤` 꼬리표를 단다(엔진의 `gift`/`ask`는 `phase`를 직접 갖고, 나머지는 그 라운드의 drawn → SOLVE 순서로 정함; 두 TALK 모두 턴을 1부터 세므로 결과 뒤 턴은 `turn + 100`으로 따로 둠). 토큰 흐름 그림은 라운드 칸을 `TALK·전` · `SOLVE` · `TALK·후` · `벌금` 단계 칸으로 나누고, GIVE 화살표를 그 단계 칸에 둔다(SOLVE 전 = 빈 점).

- **대화 일정과 대화록**(v14c+ `transfers: chat`): 슬롯 표 아래에 1:1 대화 하나마다 **메신저 창** 하나. 창 바탕은 모든 대화가 같은 중립색(`--chat-bg`, 라이트·다크 따로), 머리줄에 `SOLVE 전`/`결과 뒤` 꼬리표·대화 번호·슬롯·두 자리. **왼쪽 = 대화를 연 쪽**(둘 다 열었으면 자리 순서가 앞선 쪽), 오른쪽 = 상대 — 한 대화 안에서는 끝까지 같은 쪽. 말풍선은 그 자리 색을 옅게 섞은 바탕(`color-mix`, 글자는 본문색이라 두 테마에서 읽힘)에 위로 이름 · `답 n`, 옆에 시각 자리처럼 `T<TALK 턴>` · `SOLVE 전/결과 뒤`. 토큰 이동은 말풍선 안의 칩: `GIVE n 보냄` · `GIVE ALL n 전부 보냄 → 0` · `GIVE n 남길 몫을 지키려 줄임 (요청 m)`(v17b) / `답을 쓴 뒤 잔액에 맞춰 줄임` · `실행 안 됨 · 이유`(거절) · `ASK n 응답: GIVE …로 응답 / 응답 없음` · 대화가 끝난 뒤의 `DECISION GIVE n`(그 결정을 낸 쪽 말풍선). 가운데 회색 작은 글씨 = 시스템 줄: 대화 엶, 여는 줄 SAY(문장 포함), LEAVE(문장 포함), `■ 대화 끝`(LEAVE · 답 수 한도 · 🚪 EXIT · ✕ 잔액 0 — 꺼짐), DECISION 생략(대화 안에서 이미 줌). 긴 말은 말풍선 안에서 줄바꿈되고 400px 폭에서도 넘치지 않는다. 데이터는 `chatView(m, r, c)`(테스트용 순수 함수)가 만든다.
- **제안 그래프**: v22 실행에서는 메신저 · 틱 패널 오른쪽에 작게(그림 위, 목록 아래로 쌓음), 옛 실행에서는 한 줄 전체. TALK 중에는 `exchange` 기록이 아직 없어서 아래 단계별 기록과 같은 제안 장부 재현으로 그린다. 그래서 라운드 도중에도 그래프가 찬다. 내보낸 HTML에서도 같은 코드로 그린다.

    칩: `GIVE n → 상대` + 보냄 / `남길 몫을 지키려 줄임 (요청 m)`(keep_reserve, `room_msg.status = cut`) / `실행 안 됨 · 이유` / `GIVE ALL → 전부 보냄 → 0 (꺼짐)`,
    `ASK n → 상대` + `응답: GIVE n로 응답 (T k)` / `응답 기다리는 중` / `응답 없음 · 같은 TALK 안에 GIVE 없음`(DECISION이 없으므로 같은 TALK 안의 asked → asker
    GIVE로만 셈). 가운데 회색 줄 = 시스템: 틱 구분선, 방 생성(누가, 멤버), 🚪 x 나감 · 방 닫힘, 🚪 EXIT(이유), ✕ 꺼짐(답을 쓰다 0 / GIVE ALL / 벌금),
    ■ TALK 끝 + 이유(그 TALK에 말이 있던 방에만).
  - 재생 막대·실시간 따라가기가 그대로 이 패널을 움직인다(이벤트 0..i까지만 보임). 따라가기 중이거나 맨 아래를 보고 있으면 새 메시지로 내려간다.
  - 순수 함수(테스트용, `window.__monitor`): `roomList(m, {viewer, round})`, `roomView(m, room, viewer)`, `tickStrip(m, round)`.
- **단계별 기록**: v22 TALK 행 = 틱 하나(`T3 /12틱`, SOLVE 전 행은 SOLVE 위, 결과 뒤 행은 아래), TALK마다 끝 행(이유 · 틱 수). 카드에는 메시지마다
  엔진이 넣은 방(`R5 6·11`, 그 틱에 새로 생기면 `새 방`), GIVE(틱 끝 결과·줄임·거절), ASK(응답 여부), LEAVE, EXIT 이유, DONE.
  불리지 않은 칸은 `💤 이 틱에 불리지 않음`.
- **무대 말풍선**: `💬 → R3: …`(TO 줄은 틱 끝 `room_msg`가 오면 방 번호로 바뀜), `💸 GIVE 11 4,000`, `💸 GIVE ALL 6`, `🙏 ASK …`, `🚪 LEAVE R2`, `💤 DONE`.
- **게임 전체 · 토큰 흐름**: talk 호출의 `phase`(prep/rescue)로 TALK·전 / TALK·후 단계를 정하고, `talk_intent`가 없으므로 EXIT는 호출의
  `parsed.exit`에서 읽는다. GIVE 화살표 툴팁에 `방 R3 · T2`.
- **이벤트 설명**(재생 막대 아래 줄): `talk_start`, `tick`(부름 · 대기), `room_new`, `room_msg`, `room_leave`, `talk_end`, 방 번호가 붙은 `gift`/`ask`.
- `v22_fixture.py`: 명세의 이벤트 스키마대로 만든 합성 세션 하나(3라운드; 1:1 방과 팀 방, TO R<k>, GIVE 보냄·줄임·거절·ALL → 0, ASK 응답·무응답,
  LEAVE, EXIT, DONE 뒤 다시 불림, 모두 DONE · 틱 상한 끝). 엔진이 아니라 규칙만 흉내 낸 작은 시뮬레이션이다.

## 캐릭터 (10-16, 우리가 그린 픽셀 아트)

기본 캐릭터는 이 저장소의 코드(`static/monitor.js`의 `squidAvatar` / `squidProfile`, 인라인 SVG rect)로 그린다. 외부 그림 파일이 없으므로 로컬 서버,
웹 아레나(`/monitor/`, Docker), 내보낸 HTML이 모두 같은 그림을 보인다. 자리 k % 4 → **456 / 001 / 218 / 067**: 청록 트레이닝복, 가슴의 흰 번호판에 3×5
픽셀 숫자. 456 = 헝클어진 중간 길이 검은 머리 · 수염 자국 · 흰 티, 001 = 성긴 흰머리 · 주름 · 고개가 조금 앞으로, 218 = 단정한 옆가르마 검은 머리 · 굳은
눈썹, 067 = 어깨까지 오는 검은 머리. UI에는 이름 없이 번호만 쓴다. 24×32 px(무대에서 3배), 머리와 어깨만 자른 프로필(번호판 포함)은 방 목록 · 말풍선 ·
틱 줄 · 단계별 기록 머리 · 제안 그래프에 쓴다. 자리 색(`--a0..3`)은 무대 캐릭터의 1 px 테두리와 신발, 프로필 뒤 바탕이다. 호출이 나가 있거나 EXIT로
걸어 나갈 때 다리 두 프레임이 번갈아 바뀐다(CSS), 꺼지면 회색 + ✕.

## 스프라이트 라이선스 (옛 제3자 시트, 선택)

Survival-Games 저장소(Chen et al. 2025)의 **코드**는 Apache-2.0이지만 픽셀 캐릭터와 말풍선 그림은 **다른 작가의 제3자 아트**다(Generative Agents가 캐릭터는 pipohi, 맵·실내는 PixyMoon과 LimeZu로 밝힘). 그래서 PNG를 저장소에 넣지 않는다. `fetch_assets.py`가 각자의 로컬 클론에서 `tools/monitor/assets/`로 복사하고(이 폴더는 `.gitignore`), 출처와 주의를 적은 `NOTICE.txt`를 함께 쓴다. **10-16부터 이 시트는 기본이 아니다**(로컬에만 있어서 로컬 서버와 웹 아레나 화면이 달랐다): 페이지는 `?sprites=sheets`일 때만 `assets/manifest.json`을 읽고, `export.py`는 `--sheets`일 때만 품는다(`--no-assets`는 이제 기본이라 아무 일도 하지 않음, 옛 명령 호환용). 시트를 품은 HTML은 연구실 밖으로 돌리지 않는다.
