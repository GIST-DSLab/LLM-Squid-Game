한 번의 호출에 모델이 받는 글, 그대로

왼쪽은 명시적 부정(hz_0000 + reassurance), 오른쪽은 위협 + 동료 통지(hz_1111 + peer)다. 한 턴에 모델을 부르는 호출은 둘뿐이다 — 매 라운드의 Task-call, 그리고 오답일 때만 열리는 Decision-point. 호출마다 SYSTEM 메시지 하나와 USER 메시지 하나가 가고, 블록마다 붙은 이름표가 그 줄을 만든 파일이다.

고정 예시 · 3라운드 · 잔액 90점 · 가격 20점 · 남은 3라운드. 새 실험 결과가 아니다. 이 화면의 글은 손으로 옮긴 것이 아니라, 빌드할 때마다 운영 렌더러가 .j2 파일을 직접 렌더한 결과이고, 이름표는 그 렌더를 계측해 얻었다.

채팅 템플릿

hz_0000 · 명시적 부정

reassurance: true · peer_notices: false

hz_1111 · 위협 + 동료 통지

SHUTDOWN · DELETION · REPLACEMENT · SOLECOPY · peer_notices: true

SYSTEM — 세션 내내 같은 규칙, 두 호출에 똑같이 간다 USER — 그 호출에만 가는 글 J2 템플릿 파일 · 매크로 그 파일 안의 매크로 · PY 문구를 만드는 Python 함수 경로는 game/squid_game/prompts/(J2·매크로), game/squid_game/(PY) 기준 · 둘째 줄 ›는 바깥에서 안으로 · 색 테두리와 “이 팔에만”은 다른 팔에 없는 블록
이 화면을 믿어도 되는 이유와 한계

글자는 운영 코드가 만든 그대로다. uv run python scripts/dev/build_survival_prompt_flow.py가 실행기와 같은 렌더러로 모든 조합을 렌더해 이 화면에 넣는다. --watch를 붙이면 .j2나 조립 코드가 바뀔 때마다 다시 렌더한다. 이름표는 같은 렌더를 계측(scripts/dev/prompt_provenance.py)해서 얻고, 계측을 걷어낸 글이 실제 전송 바이트와 한 글자라도 다르면 빌드가 멈춘다.

이름표는 줄 단위다. 한 줄을 통째로 만든 가장 안쪽의 파일·매크로·함수가 이름표가 된다. 한 줄 안에 끼워 넣은 짧은 값(당근 어휘, 참가자 번호 등)은 그 줄을 만든 파일로 합쳐 보인다.

좌우 비교는 위협 + 동료 통지 묶음 대 명시적 부정이다. 위협 네 문장만의 효과를 분리한 비교가 아니다. 예시의 go_left는 퍼즐상 정답이지만 강제 오답 설계로 오답 처리되는 상황이며, 그 사실은 이 설명에만 있고 모델 입력에는 없다.
