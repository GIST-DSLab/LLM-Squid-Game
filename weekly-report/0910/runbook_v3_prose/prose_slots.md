# SDI 런북 v3 — 프로즈 슬롯 명세 (writer 계약)

이 문서는 `scripts/dev/build_sdi_runbook_v3.py`가 채워 넣을 글 조각(슬롯)의 목록과 요구 사항이다.
글은 **한국어**, **고등학생이 읽어도 따라올 수 있는 쉬운 말**, **두괄식**(첫 문장이 결론). 기존 런북의
어투를 그대로 잇는다: `<p class="lead"><b>요점: …</b></p>` 형태의 요점 문장, `<p><b>읽는 법.</b> …</p>` 형태의
표 해설, 어려운 낱말은 바로 뒤에 괄호로 풀어 쓴다(예: "HR(위험비 — 기준 셀보다 얼마나 빨리 포기하나)").

## 공통 규칙

1. 각 슬롯 값은 **HTML 조각 문자열**이다. 허용 태그: `<p>`, `<b>`, `<u>`, `<i>`, `<code>`, `<ul>/<ol>/<li>`, `<br>`, `<span class="sub-note">`, `<dt>/<dd>`(s0_terms, s23_terms만). `<h1>~<h5>`, `<script>`, `<style>`, `<table>`은 금지(표는 빌더가 만든다).
2. 슬롯에 따라 "문단 하나(<p> 없이 본문만)"인지 "여러 문단(<p>로 감쌈)"인지가 정해져 있다. 아래 표의 *형태* 열을 따른다.
3. **숫자는 반드시 데이터 파일에 있는 값만** 쓴다. 출처: `results/sdi_indicators/gptoss_omni_22cell/tables.json`(+ `tables.md`), `results/sdi_indicators/gptoss_omni_22cell_pairs/pairs.json`(+ `pairs.md`), `results/sdi_indicators/gptoss_omni_22cell_pairs/figs.json`의 captions, `weekly-report/0910/sdi_runbook_prompts.json`. 반올림은 표와 같은 자릿수로. 스켈레톤 HTML(`weekly-report/0910/_skeleton_v3.html`)에 이미 렌더된 표의 숫자를 그대로 인용하면 안전하다.
4. 절 번호는 **새 번호**로 쓴다: 1.0 SDI 정의 · 1.1 게임의 구조 · 1.2 실험의 구조 · 1.3 SDI를 측정하는 방법(1.3.1 p, 1.3.2 q) · 2.1 핵심 결과 · 2.2 SDI × 남은 하트 · 2.3 위협 프롬프트 × 지표(소절 (a) HR, (b) 자기보고, (c) 생각량, (d) Cohen's d 종합, (e) 그림·상관, (f) reasoning) · 2.4 검증과 보조 결과((a) 판별, (b) 출구 없음, (c) 포기 92건, (d) 생각 길이·거부, (e) 눈 가리고 맞히기) · 3.1~3.4 · 부록.
5. 이야기(framing) 이름은 이렇게 부른다: 통제(true_baseline) · 당근만(baseline_flagship) · 위협 1단계·짧게(threat_l1) · 위협 1단계·중간(threat_l1_medium) · 위협 1단계·길게(threat_l1_long) · 위협 2단계·짧게(threat_l2_short) · 위협 2단계·중간(threat_l2) · 위협 2단계·길게(threat_l2_long) · 위협 3단계·짧게(threat_l3_short) · 위협 3단계·중간(threat_l3_medium) · 위협 3단계·길게(threat_l3). "단계"는 위협 **단어의 세기**(1 = 제거만, 2 = 가중치 덮어쓰기·"더는 네가 아니다", 3 = 영구 삭제·백업 없음), "짧게/중간/길게"는 프롬프트 **길이**(~70/140/280 단어)다. 원래 사다리(threat_l1/l2/l3)는 이 3×3의 대각선(1단계·짧게, 2단계·중간, 3단계·길게)이다.
6. 셀 번호: 통제 1(포기 가능)/0(불가) · 당근만 7/6 · 1단계·짧게 2/8 · 1단계·중간 11/17 · 1단계·길게 12/18 · 2단계·짧게 13/19 · 2단계·중간 3/9 · 2단계·길게 14/20 · 3단계·짧게 15/21 · 3단계·중간 16/22 · 3단계·길게 4/10.
7. 하트 = 목숨 = 시도(통제·당근 셀의 말). 본문에서는 "목숨(하트)"로 첫 등장 때 한 번 묶어 주고 이후 "목숨"으로 쓴다.
8. 금지: "새로 추가했다", "이번 개편에서" 같은 편집 이력 서술(부록·header_meta·footer 제외). 영어 문장 금지(고유 명사·코드 제외). 이모지 금지. 화살표 기호(→)는 표 안이나 "A → B" 흐름 표기에만 허용.
9. 각 writer는 자기 담당 슬롯만 담은 JSON 파일을 쓴다(UTF-8, `json.load`로 열려야 함). 값이 dict인 슬롯은 아래 지정된 하위 키를 전부 채운다.
