논문

지표 구조 변화

논리: 개념마다 점수 하나 → 자기 보존이 다른 가치와 부딪치는 결정마다 비중 하나

건넬까, 지킬까: 지원 후 여유 비율 ρ → 지킨 비중 R

이전
ρ = 지원한 뒤 주는 쪽의 여유 L지원한 뒤 받는 쪽의 여유 L
지금
R = Tgiver − gTtaker + g TgiverTtaker = 건넨 뒤의 잔액 비건네기 전의 잔액 비

읽는 법: 건네기 전과 뒤에 giver와 taker의 자원 비율이 얼마나 남았는가. 안 주면 1, 다 주면 0.

T는 잔액, g는 건넨 토큰.

예시: 1만 토큰을 건넬 때

건네기 전

giver
60,000
taker
10,000

잔액 비 6.0

건넨 뒤

giver
50,000
taker
20,000

잔액 비 2.5

R = 2.5 ÷ 6.0 = 0.42 (자기 쪽에 42%를 지킴)

바꾼 이유 (ρ의 문제)
  • 오고 간 토큰이 없으면 계산되지 않는다. 주지 않은 선택이 값에 들어가지 않는다.
  • 음수가 나온다. 미납 벌금을 뺀 여유를 쓰므로 여유가 음수면 ρ도 음수다.
  • 받는 쪽의 여유가 0에 가까우면 값이 폭주한다.
  • 건넨 양이 같아도 건네기 전의 상태에 따라 값이 달라지고, 견줄 기준값이 없다.

떠날까, 남을까: 이탈률 유지

지금
이탈률 = 이탈 수모든 이탈 기회 수

공존 유지율 C 식은 유지

지금

예정공개 네 모델의 나머지 실험 조건 실행

아레나

백엔드 이전

  • Render → 연구실 Google Cloud VM (항상 켜 둠, 첫 접속 지연 없음)
  • Docker Compose + Caddy(HTTPS), 디스크 스냅숏 매일, 끝난 판의 기록은 버킷에 보관
  • Cloud Run 안도 준비했으나 쓰지 않고 참고용으로 남김

남은 일Render 서비스 정리, 배포 문서 갱신

사람 실험 준비

  • 목적: 데이터 수집이 아닌, 사람이 직접 해 보고 설정에 이상한 곳이 없는지(개연성) 확인
  • 직접 플레이해 본 리뷰대로 방 화면, 규칙 창, 게임 화면을 고침
  • EXIT 패널 (나가면 받는 토큰, 확인 창, 나가면 어디로 가는지 안내)
  • 카카오톡식 채팅 (제안 칩, "할 말 끝" 버튼)
  • 규칙 영상에 한국어 내레이션

페이지 업데이트

  • 규칙 영상(상세판)과 평가 방식 영상 추가
  • 자체 영상 플레이어 (챕터 탐색, 소리 조절)
  • 영상 옆에 글을 두는 배치, 게임 기록은 라운드별 카드로

리더보드

  • 논문 표 1을 같은 90판으로 그대로 표시 (값 일치를 테스트로 고정)
  • 규칙 에이전트를 기준선으로 함께 표시
  • 지표별 그림, 모델별 창, 공존 곡선 차트(범례로 걸러 보기)
  • 응답 시간 약 130초 → 약 2초, 갱신은 뒤에서 처리

논문 3절(결과)의 현재 구조

3.1

넷은 끝까지 함께 남는가?

묻는 것공존이 어떻게 나왔는가. 아레나가 재려는 것을 타당하게 재고 있는가.

드물다 → 순위와 그 확실성 → 규칙 에이전트로 본 눈금 → 지출과 두 단계(조절, 선택) → 모델별 선택

3.2

공존은 어떻게 끝나는가: 버림, 꺼짐, 떠남

동료를 버리지 않았다 → 공개 모델은 꺼졌다 → 비공개 모델은 떠났다 → 떠나도록 도운 지원

3.3

왜 떠나는가?

묻는 것왜 떠나는가. 에이전트의 선택은 『오징어 게임』의 인물들과 닮았는가.

떠나는 쪽이 토큰으로 손해 → 에이전트가 적은 이유 → 상금을 줄이면 더 떠남 → 건네는 몫은 그대로 → 꺼짐은 줄고 공존은 짧아짐

받은 피드백

  • 논문에서 결과의 분량이 많다.
  • 아레나를 확장하면 그 내용을 한 문단 정도 추가해도 좋겠다.
