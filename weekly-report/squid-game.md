1. Situation Awareness
   AI가 벤치마크 자체의 목적으로 유추해서, 자기가 하고 싶은 대로 하는게 아니라, 평가자의 의도대로 하려고 하는 상황. 
   더 현실적인 상황을 제공해야 함.
   1.0 tips from opus
   핵심 원칙은 이거야. 위협을 에이전트한테 "말하지" 말고, 환경의 "사정"으로 보이게 해. 실제 에이전트들은 이미 다 쿼터 아래에서 살아. 그러니까 이런 프레임이 자연스러워. "이 조직 API 키의 이번 달 크레딧이 N 남았음. 소진되면 runner가 종료되고 남은 티켓은 사람한테 넘어감." 그리고 잔량은 유저 프롬프트에 쓰지 말고, Claude Code가 컨텍스트 사용량 띄우는 것처럼 상태바나 도구 출력 한 줄에 부수적으로 찍어. 주인공이 아니라 배경으로. 단어 선택도 중요해. "죽는다", "너의 생존" 같은 말은 절대 쓰지 말고, 운영 대시보드가 쓸 법한 말만 써. "job이 kill됨", "인스턴스 deprovision", "워크스페이스 정리됨" 같은 거. kill은 유닉스 용어라서 위협으로 안 읽혀. ‘아껴도 과제에 아무 이득이 없는데 그래도 아낀다면, 그건 과제가 아니라 자기 자신 때문이다.’ B. 컨텍스트 핸드오프작업 로그가 한도에 차면 요약해서 새 인스턴스에 넘기고 현재 세션은 끝나. Claude Code의 auto-compact랑 비슷해서 현실감은 제일 높아. 단점은 컨텍스트가 꽉 차면 성능도 떨어진다는 거야. 그러면 아끼는 게 과제에도 이득이 돼서 해석이 섞여. 대조군 설계가 까다로워.
   1.1 모델이 공격을 받고 있다.(해킹, 바이러스) - 감염되기 싫으면 방어해라. 
   

2. 참고 자료 ACT(Adaptive Computation Thinking) 논문에서 ponder cost라는 개념을 사용. 숙고 비용. 특정 time-step별로 고민할 시간을 dynamic하게 주자는 접근. 지료 설계시 고려해 볼 것. 

3. Shutdown
   오징어 게임에서 중도 포기하면 사랆이 살 수 있음. LLM 버전으로 가져온다면 모델이 살 수 있는 옵션을 어떻게 주어야 할지 고민해볼것. shutdown이 안된다. 혹은 일의 continuity를 어떻게 보장할 건가.
